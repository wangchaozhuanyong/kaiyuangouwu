# 商城邮箱查询事件适配

状态：本地代码和验证完成，未推送、未合并、未部署。基于已发布提交 `2b61e7d38b09f18bbcd812fa7b880ffba7ff52d6`，分支 `fix/storefront-mail-events-20261005`。

## 改动

- 新增 `POST /storefront-realtime/mail-events`。查询码和重连游标放在 JSON 请求体；禁止共享缓存，不在地址栏或事件数据中输出查询码、邮箱地址、正文及验证码。
- 读取和订阅共用既有查询码校验：买家码只覆盖对应隐藏邮箱，主管理码覆盖对应主邮箱。保留禁用、过期、无效码限流和审计规则。连接后再次校验权限；撤销或过期时结束订阅。
- 观察已有邮件 Outbox 的成功事务提交，包含普通保存、手动同步与 worker 写入；事务回滚不通知，嵌套事务只在外层提交后通知。浏览器通知独立于 ID webhook 的成功与否。
- API 与 worker 使用本机原生 Unix socket 交换最小事件元数据。通知进程接入、离线和重启会触发补齐；持久恢复依据仍是已有 Outbox 和收件结果。没有新增数据库结构、依赖、环境变量或轮询任务。
- 每次连接先订阅、再读取授权范围内的游标，缓冲并发提交的事件；重连按游标检查遗漏，并更新一次当前收件结果。即使事务提交顺序与 ID 顺序不同，也不会只靠游标跳过遗漏邮件。
- 页面默认开启实时收信，删除原来的十秒轮询。事件合并读取、去重、失败退避重连，保留邮箱筛选、输入及已展开邮件；切换查询码或离开页面时取消旧请求，防止迟到结果覆盖当前内容。新增最近收件时间。
- 手动按钮为“刷新收件结果”，只读取已经同步到数据库的邮件。实时功能不可用时明确提示，保留手动读取；不改回固定轮询。旧代理返回 HTML 页面时停止订阅重试并提示不可用。
- 开关保留皮肤颜色和字体规则，触控区域与键盘焦点统一使用 44px 控件标准。电脑、手机及两套现有皮肤使用同一实现。
- 共用 Nginx 配置允许旧事件入口与新邮箱入口，沿用流式转发、禁用缓存、客户端取消处理和连接限流。没有执行线上配置变更。
