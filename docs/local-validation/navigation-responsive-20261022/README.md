# 商城加载与页面切换整改验收

本次保留页面最终布局、业务内容、商家图片、权限与交易规则。实现目标立即响应、目标区域占位、单个中央延迟反馈和读取归属隔离。

## 修复内容

- Router 叶路由立即提交目标占位，数据由现有 Query 接管；已缓存目标直接呈现。
- 冷切换期间保留实际手机页头、返回入口和底部导航；URL、选中项与正文属于同一目标。
- 超过 200ms 的主要反馈位于可见内容区域中央；后台错误不再通过 CSS 隐藏导航反馈。
- 十秒为加载较慢，实际失败或断网才进入错误；当前区域重试执行对应的真实读取。
- 搜索、订单分页只在列表尾部反馈；可选模块不延长 page-ready。
- app-owned 表示接管完成；page-ready 表示目标必要内容就绪。
- 移除查询更新时重复解析公开首屏 JSON、正常后台更新导致的错误提示订阅变化、重复预加载和分类地址规范化等待。
- 品牌图片复用 SafeImage 并保留原候选及原图回退；关闭的筛选表单、非当前业务预加载元数据移出启动路径。

## 本地证据

- 原版本目标反馈复现失败已保存在 `baseline/`，失败过程未删除。
- 首轮全量商城测试：264 文件，3283 条通过、9 条旧断言/夹具失败；4 个失败文件随后 82 条定向通过。末轮变化的 9 文件 155 条通过，含分页不启动全局提示的回归。
- 手机/桌面真实构建浏览器：10 个滚动、滚轮、登录草稿、读取计时与重试归属场景通过。
- 10 个 SSR 接管场景通过，原始页面节点与关键几何保持；慢冷启动/刷新、三店铺语言币种、请求失败/断网/十秒慢读共 8 场景通过。
- 手机中文、桌面英文、手机英文热 SSR 的即时反馈均通过；首次阻塞目标代码、快速返回、迟到恢复与缓存往返均无串页；每帧最多一个全局加载面。
- 普通环境实测：目标反馈最大 66.9ms；最后一次缓存返回首页呈现 20.3–25.6ms。第一次首页内容人为阻塞，仅用于交互归属验收，不作为实际加载性能。

- 商城完整构建、TypeScript、体积门槛、交互规范、共享代码/发布策略检查已通过。接入主线锁文件后，按远端相同命令重新验证商城与后台预览产物，最终结果见 acceptance.json。
- 当前构建体积：入口 377KiB；启动闭包 JavaScript 731410B；首页 995291B；分类 954059B；登录 792002B。未调整预算。
