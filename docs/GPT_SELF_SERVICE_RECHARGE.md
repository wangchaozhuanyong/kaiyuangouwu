# GPT 自助充值插件接入说明

## 已实现范围

商城共用页面为 `/gpt-recharge`，已确认采用方案二紧凑表单。Plus、Pro100、Pro200 分别对应 `plus`、`pro_5x`、`pro_20x`；Pro500 为禁用展示项。实际套餐取兑换码绑定结果，公开提交接口不接受套餐参数。

浏览器仅调用商城 Shop API：配置、验码、提交、兑换码查询和任务查询。Vendure 转接 ID 系统的专用服务接口。商城保存私有连接配置和不含原始兑换码／会话的交易回执；ID 系统保留兑换码及执行任务。

## 服务端配置（需要正式发布后配置）

1. Vendure 服务端通过现有密钥管理流程配置 `GPT_RECHARGE_ENCRYPTION_KEY`（32 字节十六进制密钥）及 `GPT_RECHARGE_ALLOWED_ORIGINS`（准确 HTTPS origin 列表）。密钥需稳定保存；已有回执时不可直接轮换或丢失。
2. ID 系统服务端配置独立的 `ONLINE_RECHARGE_VENDURE_KEY` 和准确来源地址列表 `ONLINE_RECHARGE_VENDURE_SOURCE_IPS`。来源地址是可信代理处理后的 Vendure 出口地址，不能填终端用户地址或放开任意来源。
3. 在商城超级管理员的“GPT自助充值”配置中，针对指定店铺填写允许列表中的服务地址及独立服务凭证，开启服务。配置带版本校验，服务凭证不会回显，更新后清空输入框。
4. 在当前店铺的客户端插件中启用并发布 `gpt-recharge-entry`。后台连接开启与已发布入口均满足后，才允许验码及新提交。首期只配置指定自营店；默认其他店铺关闭。
5. 使用项目正式迁移流程应用 `1792152000000-add-gpt-recharge`；不得使用同步建表替代正式迁移。本任务没有连接或迁移生产数据库。

执行地址、服务凭证和加密密钥不得进入前台环境变量、公开装修配置、页面文案或统计上报。示例文件只保留占位项。未在本文记录真实地址、凭证或客户资料。

## 店铺、任务与重试边界

- 同一执行源中的兑换码在首次受理／任务关联时归属店铺。HMAC 生成的不透明网站编号由数据库唯一索引跨店铺原子占用；其他店铺不能验证、查询或提交已关联的兑换码。
- 未使用且未分配的兑换码仍是持有码。首期按约定仅开放指定店铺；若未来要求购买时就绑定店铺，需另做发行端归属配置，不能把首次关联当作销售归属验证。
- 网站任务读取同时验证店铺归属和网站凭证。执行端编号／任务令牌加密保存，绝不直接返回浏览器。
- 并发点击只允许一次执行转发；提交前先查询原兑换码。断网或响应丢失后，回执持续保留待核对锁，不自动重提。
- 只有执行前校验拒绝，或任务创建事务明确回滚时，才允许返回“未受理”并重试。已受理后的映射异常、通信异常及结果读取异常均不能据异常类型释放提交锁。
- 执行端暂时查不到任务，也不能清除网站已有的不确定提交状态。查询仍显示待核对；待核对交易需由授权人员核对原任务。
- 已关闭服务／已下架入口的历史任务继续允许持原兑换码查询。查询不返回完整邮箱、供应商、支付资料、截图、执行日志或原始错误。

## 会话与安全

完整会话只经过服务端转发，不进入 Vendure 数据库、公共查询缓存或浏览器持久存储。ID 侧按现有加密、审计和事务规则处理；仅新增网站来源的终态任务 24 小时后清除会话，待核对任务按创建时间最多保留 7 天。清除会话不清除兑换码绑定、任务锁或交易证据。

公开操作分别限流，专用执行接口同时要求独立凭证与来源限制。生产还需确认可信代理和边缘限流；应用内限流为每进程窗口，不应把 CORS 当作鉴权。

## 本地联调复现

先在 ID 项目执行 API 类型检查和 API 构建，并等待构建成功退出，再从商城项目的 `packages/store-management-plugin` 运行：

```sh
GPT_RECHARGE_ID_PROJECT='/absolute/path/to/ID-project' bunx vitest run --config e2e/gpt-recharge.vitest.config.mts
```

该检查使用实际商城接口客户端、响应解析、GraphQL schema／resolver、转接服务、SQL.js 回执迁移及 ID 系统 Nest HTTP 控制器／拦截器／任务服务／任务仓库。ID 数据层用内存适配器，监听地址仅为本机随机端口，不启动整套 ID 网站、真实数据库或执行器。测试凭证全部为明确的合成资料。

本地链路验证不代替生产 MySQL 迁移、真实执行器、第三方渠道到账或实际订阅变更验收。最后状态、检查记录及剩余发布事项见 `docs/local-validation/gpt-recharge-20261016/integration/`。

## 发布与最终验收

用户已于 2026-10-16 授权完成并发布本次功能。发布时应按两个项目各自流程冻结源码、运行受影响检查、配置私有连接、应用正式迁移，最后先回读非充值接口，再用专用测试兑换码验收受理与恢复。真实充值会产生实际交易，须明确测试账号、套餐与额度后单独验收。没有到账回执前，不宣称充值功能已上线可用或业务成功。
