# Business closure architecture-budget review (2026-09-21)

The business-closure release adds privacy, payment recovery, customer operations, fulfilment, incident response, risk governance and attribution to the existing Shop API and both administrator interfaces. The architecture-debt gate originally failed on four budgets. This review records each decision; it is not a blanket waiver.

| Budget                                                   | Previous maximum | Reviewed result | Decision                                                                                                                                                                                                                                                                                                                                                         |
| -------------------------------------------------------- | ---------------: | --------------: | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `packages/storefront/src/styles.css`                     |            1,172 |           1,117 | Extract the self-contained traffic-consent rules into `styles/traffic-consent.css`; keep the original maximum.                                                                                                                                                                                                                                                   |
| `packages/store-management-plugin/src/api-extensions.ts` |            1,372 |           1,306 | Split privacy, store-payment, and customer/governance GraphQL definitions into domain schema modules; keep the original maximum.                                                                                                                                                                                                                                 |
| `packages/storefront/src/api.ts`                         |              652 |             715 | Raise only this maximum to 715. The new lines are typed forwarding methods for the existing public `ShopApi` facade; request logic remains in its existing account, content, and referral API modules. Moving only the new forwards elsewhere would make the public API inconsistent without reducing actual code.                                               |
| `legacy-dashboard-surfaces`                              |           44,373 |          52,819 | Raise only this group maximum to 52,819. The increase is new, permission-scoped operational pages and their English/Simplified-Chinese catalogs in the existing operations-dashboard plugin. Both administrator surfaces are required by the closure plan. Moving these files outside the counted directory would evade the gate without improving architecture. |

The two raised budgets are set to the measured line counts, with no spare allowance. Their reduction targets remain 500 and 0 respectively. Follow-up architectural work should shrink the `ShopApi` facade by migrating consumers to domain clients with compatibility coverage, and migrate legacy plugin Dashboard surfaces through a separately reviewed Dashboard extension plan. Neither change is safe to mix into this release. New feature work must not silently increase either budget again.

The CI schema failure also exposed an unsafe boundary: the Shop API referenced the Admin-only `FraudRiskCase` type. Shop now has a separate customer-facing type with only the case identity, status, deadline, and appeal status. Internal scores, signals, owner IDs, and free-text administrator decisions remain Admin-only. A schema test guards this boundary, and the previously failing Admin/Shop translation-outbox acceptance passes locally.

Verification required before merging this review: the architecture-debt gate, the operations plugin type check and Dashboard i18n checks, plus affected storefront/store-management builds. The GraphQL schema extraction must preserve the combined Admin and Shop schemas; it does not add or remove resolver fields.
