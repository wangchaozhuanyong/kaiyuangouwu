## 业务与界面

| 能力 | 数字商品 | 实物商品 |
| --- | --- | --- |
| 商品信息、分类、展示图片、规格、售价、成本、供货来源 | 共用基础组件 | 共用基础组件 |
| 商品业务工作区 | `DigitalProductWorkspace` | `PhysicalProductWorkspace` |
| 可售数量 | 自动发卡读取卡密池；人工和文件使用独立限量额度或不限量 | 有效仓库库存与批次 |
| 交付 | 自动发卡、人工发布成品、私有文件版本 | 出库、物流、签收 |
| 包装、采购单位、保质期、批次、拆包 | 不接入数字业务保存契约 | 高级设置，普通商品包装换算默认 1 |
| 售后 | 按订单行和份数暂停、恢复或撤销后续领取／下载 | 退款与实际退货验收分别处理，验收后才回库 |

商品编辑保持单页，分为商品信息、规格与价格、交付与售后、更多设置。默认单规格；多规格输入名称和规格值后生成组合，支持批量价格。保留已有规格 ID 和编码，新增组合不复制库存、卡密或文件，也不自动删除已有规格。

数字商品默认人工交付、不限量；文件和人工可改为限量。交付方式可统一应用或按规格设置，文件可统一上传后绑定到多个规格。卡密导入、实际交付、入库与退款使用独立操作，显示各自结果。

系统创建时间只读显示，来源创建日期放在更多设置。供货来源由两类商品共同使用，数字商品供货关联不经过实物入库。全局说明按钮统一无边框、底色和阴影，点击阅读解释；字段标签、按钮和输入区域对齐，手机单列。商品页移除重复业务入口和教学区块。

导航按商品、订单、数字交付、实物库存、营销、店铺设置归类。数字交付提供人工待办、成品发布、通知重发和交付异常；实物库存保留仓库、批次与包装，售后提供实际验收回库。营销和系统设置沿用现有业务，此交付不表示所有低频后台页面都已重新排版。

已有订单、库存、卡密、包装规则、批次或交付资源的商品，后端禁止直接转换类型。可复制基础资料创建另一类商品；复制结果不带库存、卡密或私有交付文件。没有业务资源的商品仍可调整类型。

## 交易闭环

数字：创建及定价 → 配置数字交付 → 准备资源 → 下单预占 → 付款 → 卡密分配／成品发布／文件领取 → 按份售后。

- 卡密池在付款前预占，付款成功分配；通知重试沿用原卡密，已交付卡密不自动回到可售池。
- 人工交付保存加密成品，发布后保留原内容，增加购买数量只追加新增成品。通知失败不撤销订单页领取资格。
- 私有文件上传产生新版本，订单占用固定成交版本；新商品配置不会替换历史订单文件。文件不进入公开商品素材库。
- 限量额度与占用、消费、释放使用独立记录。未交付取消释放占用；已交付退款默认不补回份数，商家可明确调整数字额度。
- 按份退款处理中暂停对应资格；失败恢复，成功停止对应交付和下载。金额补偿不会扣减份数。已取得的卡密、已下载文件无法实际追回。
- 普通查询仅返回交付元信息；客户明确领取后才解密内容或提供下载地址。领取核验订单本人或订单确认凭证、店铺、当前付款与退款状态；下载再次检查当前资格。

实物：创建及定价 → 入库 → 下单占用 → 付款 → 出库物流 → 签收 → 退货验收 → 可售或不可售回库。

- 启用批次先分配已有库存，不重复增加仓库数量；过期和作废批次不可售，按有效批次出库。
- 自动拆包保留整箱、散件换算和来源批次、生产日期、效期、成本及操作记录。
- 退款不自动回库。实际验收数量不能超过原仓库已出库且尚未验收数量；良品恢复有效原批次，损坏或过期商品进入不可售库存。

混合订单共用一笔付款，数字填写交付邮箱，实物使用地址和配送，运费只计算实物。履约状态按各订单行汇总；数字已交付时实物仍可显示待发货。

结算协调数字额度、卡密和实物库存，按稳定顺序加锁，重复请求和交付重试不重复扣减。占用期限沿用支付单有效期，没有时使用 15 分钟。资金结果不明确时保持占用与待核验状态，不能直接取消或再次支付；明确失败才释放。迟到确认的付款保留真实支付记录，进入异常，经核对后补资源、补交付或退款。实物补交付也重新核对并锁定可用库存。

## 迁移与切换

1. 备份数据库及现有 `DIGITAL_DELIVERY_ROOT` 私有文件，新增兼容结构；先在隔离数据库演练。
2. 按具体店铺和规格预览并核对旧可售数量、占用、未完成订单、旧文件和历史交付。
3. 共享仓库、数量归属不明或未完成订单店铺归属不明时，该商品停止切换；不能复制同一余额给多个店铺。
4. 审核预览数量后，按店铺分批调用迁移。执行时重新锁定核对预览数量；可重复执行而不重复增加份数。
5. 激活后只写数字记录，旧仓库余额保留用于对账。多店商品在所有所属销售店铺完成数字迁移后才停止全局旧库存跟踪。
6. 对账可售数量、占用、未完成订单和历史交付；确认全部切换后，再处理旧运行依赖。

此交付只在临时 MySQL 中执行过迁移与交易验证，现有正式商品没有自动批量切换。旧数字商品在显式迁移前仍有兼容读取和旧交易路径。

已切换商品不能直接回滚到按旧仓库余额售卖的代码，否则可能出现双重可售。需要回退时，先停止相关商品销售、核对当前数字占用及已交付记录，再制定恢复方案；保留旧表不等于可以直接恢复旧交易逻辑。
