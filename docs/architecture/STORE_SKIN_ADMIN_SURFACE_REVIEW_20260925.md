# Store skin administrator surface review (2026-09-25)

Status: NextAdmin is the sole editor for the new skin fields in the local candidate. This does not authorize a release.

The project has not launched. The configured production `/dashboard` route serves `packages/next-admin/dist` through `NextAdminPlugin`; the release artifact does not contain a separate older Dashboard frontend. Maintaining category artwork, service and support artwork, and coupon appearance in both the older Vendure Dashboard source and NextAdmin would duplicate UI logic and create two places to diagnose save failures. The existing older Dashboard source remains in the repository; only the uncommitted editors for these new fields were removed. The backend content and coupon APIs, channel ownership, asset selection rules, and storefront rendering remain shared.

Two compatibility guards remain in the older Dashboard:

The `legacy-dashboard-surfaces` group is now **52,883 / 52,883** lines; the old limit was 52,854. The limit rises by exactly the 29 justified compatibility lines, with no unused allowance, while the target remains zero. Removing these guards would let an older Dashboard action disturb new content. Moving their files outside the audited directories would hide the growth rather than reduce it. The category banner editor, service/support image controls, coupon appearance dialog, and their dedicated old Dashboard route were removed from this candidate. Their pre-removal patch is stored in the project-owned readiness artifacts for review or recovery.

The architecture check and its two tests pass. The two older Dashboard extension entries resolve and bundle their local imports; 15 focused compatibility tests and lint of the affected old Dashboard files pass. The older Dashboard extension bundle is not a production release artifact. The actual NextAdmin static bundle was then served by a disposable SQL.js server: a synthetic platform owner logged in, switched to an active test store, selected an image from the asset library for the desktop category banner, saved it, read the published image through Shop API, and confirmed it after refreshing the editor. The same login flow created a fixed-color coupon and checked its appearance through Admin and Shop API after refresh. The commercial services and support editors saved selected artwork and published it through Shop API after fixing shared first-create serialization of default English copy. The shared serializer submits default English only while the corresponding Chinese source is unchanged; edited Chinese with untouched English follows the existing translation path. The same browser flow created a bilingual homepage announcement and both legal documents, read them through Shop API, and confirmed them after editor refresh. The legal editor now presets both routes, provides multiline bodies, and starts unpublished until the operator enables it. Its 14 focused unit tests and all 12 administrator browser cases passed after the change. These cover six editors and synthetic data; other new fields, final commit/CI, and production acceptance remain separate gates.
