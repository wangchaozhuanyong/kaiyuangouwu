# 新闻博客

各店铺独立管理的 AI 资讯插件。官方资讯采集、中文标题与正文、封面及必要示意图由后台任务生成；可选择免费来源快讯或 AI 编辑模式；免费快讯和热门 Skill 可按店铺设置自动更新，AI 编辑的新闻由管理员审核发布。

## 接入与启用

- 已在 dev-server 注册 `NewsBlogPlugin` 和新增迁移 `AddNewsBlog1793491200000`、`AddBlogSkills1793577600000`、`AddBlogSourceMetadata1793577660000`。最后一个迁移仅增加可空的来源元数据列，可重复执行。生产数据库仍保持 `synchronize: false`，本次不执行生产迁移。
- 后台入口：插件管理 → 新闻博客（`/plugins/news-blog`）。各店铺默认关闭。
- 超级管理员先保存栏目设置；然后在“客户端插件中心”添加新闻博客、启用并发布入口。
- 商城详情地址 `/zh/blog/:slug`，列表地址 `/zh/blog`。商城导航配置新增 `/blog`，可按店铺需要放到已有导航位置；不自动替换现有导航。
- 首期内容为简体中文，未生成英文文章，不创建重复的英文索引页。

权限：`ManageNewsBlog` 管理草稿、来源和任务；`PublishNewsBlog` 审核、发布及撤稿。供应商选择、预算设置、结果不明任务的费用核对仅限超级管理员；不自动修改已有角色。后台上传/预览图片沿用原有素材权限。

## 采集与写作

默认来源为 OpenAI News RSS、Anthropic News、Google 官方 RSS 中的 Gemini 内容和 Gemini API 更新记录。白名单、HTTPS、公网 DNS 校验及连接 IP 固定适用于每一跳，原文作为资料处理，不执行其中的指令。

Gemini API 更新记录跟随 Google 的官方重定向读取 `https://aistudio.google.com/docs/changelog`，请求其 Markdown 表示；新域名仅允许更新记录及官方 `.md` 路径。保留旧官方入口作为稳定的来源引用，并继续兼容旧 HTML 日期条目，以同一日期锚点和标题生成条目标识，迁移不会为既有更新创建新事件，也不影响旧文章的来源跟踪。Markdown 只将明确日期下的顶层更新作为条目，代码示例和嵌套说明不会成为独立资讯。

新条目原文读取失败时保留“资料不足”记录，来源显示失败原因；索引以后返回 304 仍会重试最近七天的不足资料。已有依据遇到短暂读取失败时保留正文，并保留最后成功读取的时间；失败尝试不会被当成新的事实依据。

调度器每五分钟检查各店铺的计划；默认每三十分钟采集，首次仅导入最近七天，新选题仅处理七十二小时内的资料。已发布来源独立跟踪：索引返回 304 也继续检查文章，每来源每轮最多跟踪十条到期记录，通常至少间隔一小时。七天限制不阻止已发布旧文更新；正文或图片版本变化可触发更新草稿，原公开版本保留到再次审核。没有足够原文的项目保留“资料不足”。停用来源不再参加新的自动采集。

每天最多三个资讯事件，按产品发布、价格/额度变化、功能更新及时间排序。采集身份使用规范 URL，更新记录使用条目标识；同一网址改标题不新建事件，相同正文的重复来源可归到已有事件。旧版标题身份按来源网址接续，不删除历史文章。相同事件与正文指纹复用任务，不重复调用。事实保存对应原文引句；标题、日期、数字和来源检查仍必须由编辑核对，自动检查不代表事实已经人工确认。不同写法的同一事件不保证自动语义合并。

## 免费更新与历史补采

在自动化设置选择「免费来源快讯（无需模型）」。该模式不调用文本、图片或复核模型，不要求供应商凭据和运营预算；每个任务预留、模型调用和收费均为零。已有网站和服务器的费用不属于模型接口费用。

- OpenAI 等官方 RSS 原文入口被限流或拒绝访问时，免费模式可使用不少于 80 字符的真实订阅摘要，明确标明摘要依据和全文不可读；缺少有效摘要仍保留资料不足。AI 编辑模式仍要求充分原文，不将短摘要扩写成长文。
- 四个官方源每 30 分钟检查一次，按重要性、72 小时时效及产品分布选题，每店每天最多 3 条；没有可核对更新时不凑数。中文栏目和说明配合原文短摘录，保留未翻译原句，不冒充中文长篇原创解读。
- 勾选免费自动发布后，仅来源整理器的完整结果、素材和版本检查全部通过才发布；人工修改、来源不完整或版本变化均保留待审。旧文章更新生成新草稿，不直接覆盖公开快照。
- Skill 每日最多一条，使用同一真实榜单和 GitHub 原文适配器。免费复核重读固定提交的文档，核对用途、名称、内容指纹及最近观察到的仓库收藏数，不调用模型。
- 来源原图先下载为后台候选。同店已发布快照中确认过的相同图片文件、原图地址与来源页面可自动复用为封面；未确认或出处变化的图片仍保留私有候选，公开封面使用本站免费矢量模板。主动选择主题封面会保留该选择，免费任务不会调用生图接口。
- 来源工作区的历史回放只向超级管理员开放，明确日期范围，最多 31 个已过去的日期。按每天至多三条资讯和一条 Skill 复用正常任务、去重、配图、发布链路，任务恢复不会重复选题。
- 历史 Skill 只选择长期榜单候选，并读取回放开始前已存在的固定 GitHub 版本。收藏数和榜单排名属于本次观察，不能还原历史热度。没有符合条件的候选时留空，不虚构当日热门。
- 补录在正文注明模拟日期、来源日期和实际采集日期；公开发布时间是实际发布时刻，不能假称网站一个月前已经发布。
- Gemini 官方 RSS 只保留有限窗口；历史回放补读官方分类归档中实际提供的带日期卡片。各源的可回溯范围以公开资料为准，不承诺恢复已经消失的归档。

免费任务遇到临时网络错误可按 1、5、15 分钟退避，最多恢复三次；调度器在下一次到期检查时继续。进程中断后按已保存的正文、配图和版本检查点续做，不重复创建文章或覆盖人工版本。旧版免费失败记录可安全恢复一次；新发生的资料错误、设置变化或人工版本冲突保留待处理，不自动循环。已经发送或结果不明的收费调用继续保留预算，不能自动重试。

每日资讯额度统计有效任务及已生成文章。确定没有外部调用且没有文章的免费失败事件释放名额；恢复任务须在店铺事务锁内重新占位，跨日恢复也遵守当天额度。已有草稿和收费事件的名额不会被当成零产出的免费失败释放。

免费 Skill 用途优先读取说明的主要句子，忽略附带触发词及否定用途；不确定时保留原文用途说明，不强加中文分类。热度卡片的 Star、榜单、排名、趋势和采集时间作为一份快照刷新，保留人工稿件和正文原始观察记录。

## 热门 Skill 每日推荐

- 博客分类栏增加“热门 Skill”，筛选地址 `/zh/blog?category=skills`。列表提供用途介绍与“查看 GitHub 仓库”按钮，详情展示仓库、固定版本目录、Star 和采集时间。
- 首期博客只有中文公开版本；英文商城中的博客入口也指向 `/zh/blog`，不生成重复的英文文章索引。
- 超级管理员在自动化设置中单独启用，默认关闭。默认马来西亚时间 09:00，每店每天最多一条；首次启用当天可立即选题，正常计划停机只补当天；历史日期由独立回放任务补采。AI 编辑新闻仍需人工审核。
- 公共候选每六小时更新（免费匿名请求窗口耗尽时，窗口恢复后继续未完成采集）：Trending 前 50、Hot 前 30，优先近期热门；没有合适的新条目时从 All Time 前 300 选择长期热门。仅接受 GitHub 原仓库、真实有效 SKILL.md、至少 1,000 Star，排除归档、禁用、Fork 和高度相似内容。Star 是仓库收藏，不代表某个 Skill 的单独点赞或安装数。
- 当前使用公开榜单 HTML，不调用需要 Vercel OIDC 的榜单 API；遵守公开 robots 规则。GitHub API 匿名请求通过数据库统一限制为每小时 40 次，其中候选发现最多使用 32 次，为发布核验保留 8 次。逐请求原子计数，复用白名单、公网地址检查和固定连接 IP，未接入新凭据。付费调用前遇到限流时，原任务延期到窗口恢复后继续，不创建重复推荐或重复预留。
- 仓库稳定 ID、目录、历史别名、正文指纹用于去重；同一个 Skill 在同店仅介绍一次，撤稿不清除去重记录；AI 编辑模式同仓库不同 Skill 至少相隔七天；免费模式优先近期未出现的仓库，候选有限时可选择同仓库其他不重复 Skill。数据表保存全局公开候选/热度、采集状态与店铺推荐历史，通过数据库唯一约束保证并发不多发。
- 中文介绍只根据固定版本 SKILL.md 和 README 生成，包含用途、适用人群、场景和限制。事实必须附可逐字匹配的原文引句；生成后另排事实复核任务，核对完整标题、摘要和正文。只有引用检查与独立模型复核均通过才自动发布，否则保留待审。两阶段分别预留和记录运营用量，复核未获预算时等待调度器，不提前发布。自动复核仍有模型误判的可能。
- 程序写入真实来源和 GitHub 地址，不执行或安装技能。默认封面使用免费本地模板。当前 SKILL.md 内同仓库、固定提交版本的图片可导入私有候选，待编辑确认用途与使用依据；不把仓库通用 banner 当作该 Skill 的效果图，也不直接使用未经确认的候选图自动发布。
- 缺少模型或预算时只采集候选，不生成或发布。来源失败、资料不足、限流或没有合格新候选时保留原公开内容并记录原因。重试继续遵守现有运营预算与结果不明核对规则。
- 自动文章标注“自动整理”，不声明人工审核；后台仍可编辑、审核发布或撤稿。热度按最新有效采集更新；原文变更产生更新草稿，人工修改不会被覆盖。技能文章暂不提供新闻来源专用的逐段重写操作，可直接编辑正文。

## 模型、图片与运营预算

复用图片工坊现有的服务端供应商与加密凭据，不读取客户会话、不调用客户生图付费流程，不扣客户钱包。

仅 AI 编辑模式需要配置文本供应商、模型和单次调用预算后才会写作。每次付费任务入队前，以当前店铺为范围持有数据库预算锁并预留额度；未知费用继续占用预留额度。供应商报告的 USD 费用、请求标识和用量单独记录，不把未报告费用视为已测得的零成本。预算为本地任务准入限制，实际结算以供应商账单为准。

新闻图片优先提取当前原文的 OG、Article JSON-LD 和正文区域图片，最多保留三张候选，排除相关推荐、导航及缩略图。候选仅允许该来源配置的官方图床与路径，重定向逐跳执行公网校验；下载上限 8MB，校验真实栅格格式与像素限制，按店铺和文件指纹去重，压缩为本站 WebP 素材。原图保留完整画面，不叠加标题或误标 AI 图。

后台支持选择原图封面、最多两张正文图、编辑图注及查看出处；原图发布前必须确认使用依据。导入新候选不会覆盖人工封面和正文图，异步写入继续校验版本。原图失败时，尝试现有生图接口或免费模板；也可主动选择“使用主题封面”。AI 插画由程序绘制中文标题并标注示意性质，模板显示“主题封面”。教程和对比文章按内容生成流程或来源要点示意图。

图片使用现有响应式图片预设；草稿及未选中候选需要后台身份，只有当前店铺已发布快照引用的素材可公开，客户头像不会被转为博客公开素材。公开网页可读取不代表图片使用依据已经确认。

确定未发送付费请求的失败任务可以定向重试。已发送但结果不明的任务禁止自动重试；超级管理员需先核对供应商结果、确认未完成并登记实际费用，再单独重试。重试属于新调用，会重新预留预算。

## 审核、版本与公开读取

编辑、配图和生成任务均携带文章版本。后台刷新保留未保存草稿，版本变化时提示冲突；异步任务不能覆盖较新的人工保存。发布记录实际管理员、时间和版本；修改已发布文章只影响草稿，审核后才替换公开快照。撤稿保留历史及原网址。

公开列表仅返回摘要所需的数据，正文在详情读取；候选标题、生成事实记录、配置和运行日志不进入匿名响应。公开 HTML、前台接管、站点地图与图片授权使用相同发布状态，仍遵守店铺的营业与 SEO 收录策略。

后台文章列表使用 `newsBlogArticleList` 的服务端关键词、状态和分页，默认每页 25 条，返回总数；列表不携带完整正文和私有图片候选，详情单独读取。旧 `newsBlogArticles` 保留兼容，当前后台不再依赖其前 200 条结果。

## 本地验证

在仓库根目录运行受影响的定向检查：

```sh
bun run --cwd packages/news-blog-plugin build
bun run --cwd packages/news-blog-plugin test
bun run --cwd packages/next-admin check:feedback
bun run --cwd packages/storefront check:interaction
node scripts/check-migration-registry.mjs
node scripts/check-storefront-unification.mjs
```

迁移测试位于 `packages/dev-server/migrations/add-news-blog.spec.ts`；商城测试为 `blog-route.spec.ts`、`blog-content.spec.tsx`；后台真实 Apollo/schema 交互测试为 `NewsBlogArticleEditor.spec.tsx`。`packages/storefront/e2e/news-blog/preview-server.mjs` 使用明确标注的合成内容和实际构建产物验收，不连接生产服务。

真实 MySQL 联调文件为 `packages/dev-server/e2e/news-blog.mysql.e2e-spec.ts`，使用真实数据库、数据库队列、GraphQL、公开页面读取、SSR 和本站图片文件。来源与模型边界使用明确标注的合成资料，不调用付费服务。测试数据库只允许位于本机 Docker socket 中、标记 `codex.project=vendure-news-blog` 且映射到 `127.0.0.1` 的一次性 MySQL 容器；测试会重建该容器中的专属测试库。取得其实际端口后运行：

```sh
CI=1 E2E_MYSQL_PORT=<一次性测试容器的本机端口> bun run --cwd packages/dev-server test:news-blog-e2e
```

测试需先构建相关后端包和商城 SSR 产物。不得使用生产或共享业务数据库。

生产发布、供应商配置和真实内容写入按具体任务授权执行；实际完成状态与未通过项以任务验收证据为准。

目录采集保留 2MB 响应限制；大型仓库只读取实际存在的 skills、.agents 或 .claude 子树。按固定文档前置声明匹配 Skill 名称，支持目录名与 Skill 名称不同，冲突同名文档不自动推荐。

历史回放遇到匿名请求窗口耗尽时保留已完成日期并自动续做；免费模式中的仓库多样性是优先顺序，同一 Skill 与相同正文仍严格去重。
