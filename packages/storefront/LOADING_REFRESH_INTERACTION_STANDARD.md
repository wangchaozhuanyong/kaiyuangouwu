# 客户端加载、刷新与交互统一标准

版本：2026-10-03。实现基线：`192c7fc648a8fe00eef1e5be73ba86786569a0d2`。范围为共用店铺客户端、桌面／手机、中英文及客户端插件；后台由独立窗口负责。此规范不授予推送、合并、部署或生产数据修改权限。

## 两端协调契约

已向用户指定的“审计管理后台加载与刷新体验”窗口发送协议及文件边界。客户端使用 TanStack Query / Router，后台使用 Apollo / React Router，均保留现有技术栈。跨端一致的是可观察行为：首载骨架、刷新保留数据、失败局部可重试、作用域隔离、写操作防重复和编辑草稿保护。后台页签保留与客户端路由滚动恢复分别实现，不互相复制缓存。根 `AGENTS.md`、后台代码、API 合约、数据库及权限支付业务不在本窗口改动范围内。

两端的店铺配置仍由 Admin 管理、Shop API 读取。客户端复用已存在的实时失效及 30 秒配置／内容回查，不新增独立内容源、不按店铺硬编码。两端规则分别归各自包，避免根规则冲突。对方反馈的实际路径及复核结果记录在交付报告中。

## 状态与呈现

| 场景         | 判定                            | 必须呈现                                   | 禁止行为                           |
| ------------ | ------------------------------- | ------------------------------------------ | ---------------------------------- |
| 首次读取     | `data === undefined` 且正在加载 | 对应布局骨架，可访问名称和 busy 状态       | 全站重复遮罩、按条目数量判断已加载 |
| 首载失败     | 无数据，error／paused           | 业务化错误、局部重试和返回                 | 把失败伪装为空列表或未开放         |
| 成功且无内容 | 已收到 `[]`／`null`／零条结果   | 明确空状态，必要的下一步入口               | 无限骨架、把零条误判网络失败       |
| 后台刷新     | 已有数据，正在 fetch            | 保留内容；超过 200ms 才显示轻提示          | 清空卡片、重置滚动／筛选／表单     |
| 刷新失败     | 已有数据，刷新 error            | 共用轻提示，明确保留上次内容、可重试或关闭 | 替换整个页面、把旧内容称为最新     |
| 追加加载     | `isFetchingNextPage`            | 保留已有条目，分页区域 busy                | 重复请求、取消正在加载的分页       |
| 追加失败     | next-page error                 | 分页区域错误与重试                         | 冒充整页加载失败                   |
| 断网         | paused                          | 全局离线反馈；无数据才用首载错误           | 轮询风暴、把暂停计作成功           |
| 版本更新     | 明确检测到不同资源版本          | 用户可选择稍后；敏感操作期间延后提示       | 把数据重试绑定到整页 reload        |

`storefrontQueryPresentation` 是状态判定共用入口，`storefrontInitialQueryError` 只给无数据查询提供替换内容的错误。Query 本身仍保留完整 error，统一反馈中心读取它；不得吞掉错误或造成功状态。

钱包可用金额等敏感值沿用原业务的确认要求：读取失败显示“暂不可用”和重试，不把缓存金额显示为已确认金额。页面其余可用内容继续保留；统一刷新规则不放宽余额或支付校验。

## 查询与刷新生命周期

1. 所有页面、功能、客户端插件复用根 QueryClient。`storefrontQueryKeys` 包含店铺、结算币种、语言；客户私有查询还包含客户 ID，查询条件包含分页／搜索／筛选。显式作用域由调用方传入，禁止刷新其他店铺、其他语言及未启用的查询。
2. `refreshStorefrontQueries` 统一刷新当前作用域的 active reads；公共重试包括内容、配置、分类、商品及其他正在使用的公共查询。页面恢复可包含当前活动私有读取。两个点击复用同一请求，刷新不启动新写操作。
3. 单项重试和追加加载显式 `{ cancelRefetch: false }`；TanStack 负责请求合并、缓存和取消。查询函数把 `signal` 传入实际 API。切换 query key 后旧请求不能更新目标 key；不能用旧 closure 把旧作用域结果写回新作用域。
4. 仍挂载但 disabled 的查询、未挂载的页面和其他 scope 不纳入统一刷新。现有支付报价／订单确认 token 的特殊 Query 由支付流程自己管理，本次不改变其生成、续期和支付逻辑，也不把它们纳入公共刷新。
5. 公共查询默认 60 秒 stale、30 分钟 GC；现有内容／配置 30 秒回查沿用业务要求。隐藏窗口不继续业务轮询，重返窗口／重新联网只刷新过期数据。不要为每个页面设置新的计时器。
6. 公共会话缓存最多保留 5 分钟，只允许现有 public 白名单；品牌配置不持久化，客户和购物车不持久化。后台刷新失败后可保留上次确认的公共数据，序列化时移除 error／failureReason，保留原 `dataUpdatedAt`，不把它包装为刚更新。
7. placeholder 只允许同店铺、同结算币种、同语言的筛选变化。用 `storefrontPlaceholderData`，不得无条件 `keepPreviousData` 展示另一作用域的数据；placeholder 状态下禁止把旧结果直接当成新条件的确认结果。

## 导航、媒体与布局

- URL 是路由和筛选状态来源。重试不改变地址；浏览器刷新、返回／前进恢复目标状态；返回已访问页面沿用现有滚动恢复。新搜索或筛选从该功能的初始分页开始，刷新数据不重置已输入表单。
- 主框架、桌面导航和手机底部导航在加载时继续可操作。`PageReadinessBoundary` 只观察路由模块、必要数据和首屏媒体，沿用数据 10 秒、媒体 3 秒的就绪期限；迟到数据不重播首载动画。查询传输有独立 20 秒超时，不改成无上限等待。
- 图片使用 `SafeImage`，保留尺寸、占位和 fallback，使用实际选中的候选判断就绪。媒体超时可降级，不能用空白或错误图片宣称成功；屏外图片不阻塞首屏。
- 状态组件沿用现有语义主题变量和响应式布局。更新提示有可访问 live region，重试／关闭键盘可达，手机触控目标至少 44px；提示不获取焦点、不遮罩页面、不禁用主导航。

## 搜索、表单与操作

- 保留现有中文 IME 组合保护、同步输入草稿与搜索建议防抖；不能在 composition 中把拼音作为最终查询。请求由 key 隔离，迟到建议不能覆盖当前搜索词。
- 表单有字段校验及明确 busy 状态，提交按钮防重复。只禁用直接相关操作，读数据刷新不锁整页。原有草稿继续由所属业务管理，不在公共查询回调中直接覆盖用户输入。
- 结果反馈区分“写入已成功、展示更新失败”和“写入失败”；不因一次读取失败再次下单、领券、支付、发邮件或创建任务。应用内已有通知／弹窗负责确认及反馈，页面不能新增浏览器 alert/confirm/prompt。
- 复杂功能的业务实时流程、支付 token 和插件本地计时有自身生命周期，先核对原契约再扩展。不得用统一加载重构改变权限、支付结算、身份认证、加密库或后端接口。

## 必须验收的场景

- 首载成功／失败／空结果／离线；缓存刷新慢／失败／恢复；多次点击仅一次读取。
- 快速搜索和筛选、中文组合输入、后退／前进、硬刷新恢复 URL；店铺／币种／语言变化清空不兼容 placeholder。
- 追加慢请求／错误／连续点击；保留之前页内容，不重复条目。
- 现有表单输入和滚动不因读数据刷新丢失；模块／图片慢或失败有明确降级。
- 390px 和 1440px 的实际客户端组件；中英文状态；已有两种主题保持语义颜色；控制台无新增异常。
- 新增功能先运行 `bun run check:interaction`，受影响 tests 和 `bun run build`。`interaction-standard.spec.ts` 随现有 tests 自动拒绝常见回退。门禁只能覆盖声明的模式，不能代替人工核对 query key、表单草稿和业务正确性。
