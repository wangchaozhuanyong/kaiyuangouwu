# 客户端加载、刷新与交互统一标准

## 2026-10-09 已确认：居中品牌首载与店铺隔离

本节替代此前首载期间保留重复页头及较小品牌文字的视觉要求。首次进入尚无可用页面时，现有 `PageReadinessBoundary` 在可见屏幕中央展示当前已确认店铺的 Logo、店名、可用英文品牌名和轻量加载提示；电脑图标96px、手机80px，原色与比例保持。已有内容后的切页、后台刷新和局部查询仍沿用非阻塞、保留内容规则，不重播整屏品牌。

- 首载组件继续挂载查询与必要状态登记，仅隐藏尚不可用的页面呈现；不建立第二套请求或就绪机制。短于200ms不强制开场，内容就绪立即进入。
- 后续确认采用“文字下细条”：完整品牌首载的三点替换为加载文案下方3px细条，手机156px、较宽屏176px；使用现有语义主题颜色与循环滑动，不显示百分比，不伪造完成进度。HTML首帧、React呈现和视觉模块失败回退保持一致；减少动态效果时静止，失败/超时移除加载条。局部及compact提示继续保持紧凑。
- 品牌从已校验的首屏快照接入当前作用域配置，店名、图标统一更新；未知、切店待确认或拒绝访问时保持中性，不借用通用默认店或历史品牌。
- 初载超时或明确失败在中央替换为静态品牌和重试，停止加载动画及busy状态。已有页面保留可操作内容，失败由所属区域或原有非阻塞提示负责，避免重复错误。重试只读取当前作用域，不重放写操作。
- 崩溃恢复不读取无归属的sessionStorage Logo，仅允许当前document已提交、归属匹配的品牌；切作用域同步失效，迟到旧owner不得回填。

## 2026-10-06 已批准方案的替代规则

本节替代下方旧版的 30 秒独立回查、宽松筛选 placeholder 和首屏媒体参与整页就绪规则。

- 配置、内容、分类、活动复用当前路由的公开聚合。唯一 `publicRefreshScheduler` 在 SSE 断线、联网且窗口可见时每 60 秒回查；手动刷新和重连复用相同查询。发布失效会取消旧代读取，禁止旧响应重新填充缓存。
- placeholder 只允许完整请求条件相同；筛选变化无目标缓存时显示目标骨架，成功的空数组仍是有效结果。分类及搜索列表统一每页 12 件，Infinite Query 缓存包含 `pages/pageParams`。
- `PageReadinessBoundary` 消费路由模块和必要查询通过 `usePageReadiness` 声明的状态，不通过 DOM 可见性或透明度推断就绪。静态骨架保留布局；普通等待提供无障碍播报，商品准备显示紧凑品牌提示；移除顶部进度线，不显示虚假百分比。图片由 `SafeImage` 自己处理占位、超时和迟到恢复，不重新启动整页加载。
- `OverlayHost` 的归属包含店铺、国家市场、币种、语言、客户和路由。所有模态弹层复用唯一 `Overlay` 的 portal、栈、焦点与引用计数滚动锁；页面不得重复处理模态 Escape 或 body.overflow。离开归属页面释放锁和遮罩，仅向仍可见的原触发元素恢复焦点。
- 保留已确认布局、商家图片和业务状态。读刷新不重放写操作，未完成真实两地指标时必须明确标记未验证。

版本：2026-10-03。实现基线：`192c7fc648a8fe00eef1e5be73ba86786569a0d2`。范围为共用店铺客户端、桌面／手机、中英文及客户端插件；后台由独立窗口负责。此规范不授予推送、合并、部署或生产数据修改权限。

## 两端协调契约

已向用户指定的“审计管理后台加载与刷新体验”窗口发送协议及文件边界。客户端使用 TanStack Query / Router，后台使用 Apollo / React Router，均保留现有技术栈。跨端一致的是可观察行为：首载骨架、刷新保留数据、失败局部可重试、作用域隔离、写操作防重复和编辑草稿保护。后台页签保留与客户端路由滚动恢复分别实现，不互相复制缓存。根 `AGENTS.md`、后台代码、API 合约、数据库及权限支付业务不在本窗口改动范围内。

两端的店铺配置仍由 Admin 管理、Shop API 读取。客户端复用已存在的实时失效及 30 秒配置／内容回查，不新增独立内容源、不按店铺硬编码。两端规则分别归各自包，避免根规则冲突。对方反馈的实际路径及复核结果记录在交付报告中。

## 状态与呈现

| 场景         | 判定                            | 必须呈现                                   | 禁止行为                           |
| ------------ | ------------------------------- | ------------------------------------------ | ---------------------------------- |
| 首次读取     | `data === undefined` 且正在加载 | 对应布局骨架，可访问名称和 busy 状态       | 全站重复遮罩、按条目数量判断已加载 |
| 首载失败     | 无数据，error／paused           | 业务化错误、局部重试和返回                 | 把失败伪装为空列表或未开放         |
| 成功且无内容 | 已收到 `[]`／`null`／零条结果   | 明确空状态，必要的下一步入口               | 无限骨架、把零条误判网络失败       |
| 后台刷新     | 已有数据，正在 fetch            | 保留内容并静默更新，不显示全局进度提示     | 清空卡片、重置滚动／筛选／表单     |
| 刷新失败     | 已有数据，刷新 error            | 共用轻提示，明确保留上次内容、可重试或关闭 | 替换整个页面、把旧内容称为最新     |
| 追加加载     | `isFetchingNextPage`            | 保留已有条目，分页区域 busy                | 重复请求、取消正在加载的分页       |
| 追加失败     | next-page error                 | 分页区域错误与重试                         | 冒充整页加载失败                   |
| 断网         | paused                          | 全局离线反馈；无数据才用首载错误           | 轮询风暴、把暂停计作成功           |
| 版本更新     | 明确检测到不同资源版本          | 用户可选择稍后；敏感操作期间延后提示       | 把数据重试绑定到整页 reload        |

`storefrontQueryPresentation` 是状态判定共用入口，`storefrontInitialQueryError` 只给无数据查询提供替换内容的错误。Query 本身仍保留完整 error，统一反馈中心读取它；不得吞掉错误或造成功状态。

钱包可用金额等敏感值沿用原业务的确认要求：读取失败显示“暂不可用”和重试，不把缓存金额显示为已确认金额。页面其余可用内容继续保留；统一刷新规则不放宽余额或支付校验。

## 查询与刷新生命周期

1. 所有页面、功能、客户端插件复用根 QueryClient。`storefrontQueryKeys` 包含店铺、结算币种、语言；客户私有查询还包含客户 ID，查询条件包含分页／搜索／筛选。显式作用域由调用方传入，禁止刷新其他店铺、其他语言及未启用的查询。
2. `refreshStorefrontQueries` 统一刷新当前作用域的 active reads；公共重试包括内容、配置、分类、商品及其他正在使用的公共查询。页面恢复可包含当前活动私有读取。两个点击复用同一请求，刷新不启动新写操作。
3. 单项重试和追加加载显式 `{ cancelRefetch: false }`；TanStack 负责请求合并、缓存和取消。查询函数把 `signal` 传入实际 API。切换 query key 后旧请求不能更新目标 key；不能用旧 closure 把旧作用域结果写回新作用域。
4. 仍挂载但 disabled 的查询、未挂载的页面和其他 scope 不纳入统一刷新。现有支付报价／订单确认 token 的特殊 Query 由支付流程自己管理，本次不改变其生成、续期和支付逻辑，也不把它们纳入公共刷新。
5. 公共查询默认 60 秒 stale、30 分钟 GC；现有内容／配置 30 秒回查沿用业务要求。隐藏窗口不继续业务轮询，重返窗口／重新联网只刷新过期数据。不要为每个页面设置新的计时器。
6. 公共会话缓存最多保留 5 分钟，只允许现有 public 白名单；品牌配置不持久化，客户和购物车不持久化。后台刷新失败后可保留上次确认的公共数据，序列化时移除 error／failureReason，保留原 `dataUpdatedAt`，不把它包装为刚更新。
7. placeholder 只允许同店铺、同结算币种、同语言的筛选变化。用 `storefrontPlaceholderData`，不得无条件 `keepPreviousData` 展示另一作用域的数据；placeholder 状态下禁止把旧结果直接当成新条件的确认结果。

## 导航、媒体与布局

- 所有页面级返回按钮复用 `components/common/page-back-button.tsx` 的 `PageBackButton`，保留所属页面的原返回回调和中英文可访问名称。可见箭头笔画左边对齐所在正文区块起线；44px 点击区与20px图形由该组件唯一管理，不在页面重复设置图形尺寸或缩小点击区。页面标题继续居中，电脑账户框架原本隐藏重复页头的规则保留。
- 普通子页面页头和正文共用 `--page-section-inset`，手机、平板与电脑同时调整；限宽阅读页共用相同限宽。搜索与认证页面复用返回控件，认证照片上的对比度样式可以保留，但位置由照片或表单正文容器管理。独立2FA入口也加载同一返回控件；翻页、轮播、重新查询与关闭操作不套用页面返回规则。
- URL 是路由和筛选状态来源。重试不改变地址；浏览器刷新、返回／前进恢复目标状态；返回已访问页面沿用现有滚动恢复。新搜索或筛选从该功能的初始分页开始，刷新数据不重置已输入表单。
- 主框架、桌面导航和手机底部导航在加载时继续可操作。`PageReadinessBoundary` 只观察路由模块、必要数据和首屏媒体，沿用数据 10 秒、媒体 3 秒的就绪期限；迟到数据不重播首载动画。查询传输有独立 20 秒超时，不改成无上限等待。
- 图片使用 `SafeImage`，保留尺寸、占位和 fallback，使用实际选中的候选判断就绪。媒体超时可降级，不能用空白或错误图片宣称成功；屏外图片不阻塞首屏。
- 状态组件沿用现有语义主题变量和响应式布局。更新提示有可访问 live region，重试／关闭键盘可达，手机触控目标至少 44px；提示不获取焦点、不遮罩页面、不禁用主导航。

## 搜索、表单与操作

- 保留现有中文 IME 组合保护、同步输入草稿与搜索建议防抖；不能在 composition 中把拼音作为最终查询。请求由 key 隔离，迟到建议不能覆盖当前搜索词。
- 表单有字段校验及明确 busy 状态，提交按钮防重复。只禁用直接相关操作，读数据刷新不锁整页。原有草稿继续由所属业务管理，不在公共查询回调中直接覆盖用户输入。
- 结果反馈区分“写入已成功、展示更新失败”和“写入失败”；不因一次读取失败再次下单、领券、支付、发邮件或创建任务。应用内已有通知／弹窗负责确认及反馈，页面不能新增浏览器 alert/confirm/prompt。
- 复杂功能的业务实时流程、支付 token 和插件本地计时有自身生命周期，先核对原契约再扩展。不得用统一加载重构改变权限、支付结算、身份认证、加密库或后端接口。

## 必须验收的场景

- 首载成功／失败／空结果／离线；缓存刷新慢／失败／恢复；多次点击仅一次读取。
- 快速搜索和筛选、中文组合输入、后退／前进、硬刷新恢复 URL；店铺／币种／语言变化清空不兼容 placeholder。
- 追加慢请求／错误／连续点击；保留之前页内容，不重复条目。
- 现有表单输入和滚动不因读数据刷新丢失；模块／图片慢或失败有明确降级。
- 390px 和 1440px 的实际客户端组件；中英文状态；已有两种主题保持语义颜色；控制台无新增异常。
- 新增功能先运行 `bun run check:interaction`，受影响 tests 和 `bun run build`。`interaction-standard.spec.ts` 随现有 tests 自动拒绝常见回退。门禁只能覆盖声明的模式，不能代替人工核对 query key、表单草稿和业务正确性。

## 2026-10-07 品牌加载视觉补充

按用户确认的手机刷新反馈，页面首载与路由模块等待复用 `PageSkeleton` 的品牌呈现：读取当前店铺配置的 Logo 和名称，底下使用轻微呼吸点；不再显示中心通用转圈文案，也不加卡片、遮罩或品牌专属布局。保留 pending、status、busy 与中英文无障碍名称。首页优惠和商品等局部等待使用 compact 轻提示，不能在同一页重复堆放大 Logo；列表首载复用品牌呈现。无 Provider 的根路由仅复用已校验 host/channel/language/currency 的服务端首屏数据；缺少品牌或图片失败时使用中性标记，不读另一店铺的旧 Logo 缓存，不发起新品牌请求。

移除网站自己绘制的顶部进度线，避免与浏览器地址栏进度条叠加。就绪登记保持当前路由模块、必要数据、超时和恢复逻辑，图片仍由 SafeImage 局部处理；普通就绪等待只提供无障碍播报，商品准备保留页面并显示紧凑品牌提示。商品准备与更新失败并发时，由错误提示优先占用共享提示区，不能遮挡重试操作。已有内容的正常后台刷新保持静默，不显示底部“正在更新”；仅更新失败由 `StorefrontQueryFeedback` 统一提供保留旧内容、重试和关闭提示，不回到整页品牌首载。用户主动提交、购物车重算等操作继续使用操作处原有 busy 反馈。减少动态效果时 Logo 和呼吸点均静止。

## 2026-10-08 品牌首帧与对齐修复

此节替代上节的中性图标占位。未知品牌只显示等待点，图片失败保留已确认的店名，不显示通用黑白店铺图标。

- HTML 根节点先提供可访问的等待状态；早期入口仅从当前 host、channel、route、语言和币种验证通过且仍新鲜的 LIVE 快照补入品牌。没有快照时继续已有请求，不增加品牌接口或持久缓存；React 接管后停止对旧节点写入。
- 所有加载区域由 `styles/skeletons.css` 统一布局。根节点首载占满可见屏幕并居中；内页仅在自己的内容区域居中，桌面不使用 `100vw` 撑开父容器；优惠等局部等待继续使用 compact。
- Logo 使用当前店铺原色，解码后显示，失败只回退原地址一次。名称使用共享 card 文字角色，长名称可换行；只让三点轻微呼吸，减少动态效果时静止。
- 页面就绪立即进入，不设置最短展示时间。已有内容的后台刷新、导航可操作性、错误重试和超时继续遵循原状态契约。

## 2026-10-08 移动端固定底栏

- 普通滚动、浏览器地址栏展开或收起时，底部导航及操作栏使用原生固定定位，不把 probe 与 visualViewport 的瞬时差值写入 bottom，避免两者跨帧更新造成上跳。
- 仅在可输入元素获得焦点、布局视口比可见视口高出 150px 以上、且原生固定底边确实被遮挡时，复用唯一 `trackFixedBottomViewport` 做正向键盘避让。浏览器已经原生对齐时不重复补偿，不使用负偏移拉低底栏。
- 失焦、键盘关闭、进入桌面宽度、缩放或无效视口几何时清除补偿；保留安全区及操作栏堆叠间距，不把键盘补偿写入文档高度或底部留白。
