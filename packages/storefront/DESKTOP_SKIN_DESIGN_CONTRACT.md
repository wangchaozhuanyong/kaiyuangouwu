## 零、两层规则

全站只允许两层设计规则。第一层是所有皮肤、前台和后台必须遵守的体验基础：内容宽度、安全边距、阅读行宽、触控目标、焦点、状态反馈、媒体比例、动效预算和首屏体积预算。第二层是皮肤表达：页面与表面颜色、强调色、标题字体、圆角幅度和阴影气质。

皮肤不得改变导航位置、信息顺序、按钮含义、表单结构、加载逻辑或数据来源。禁止为单个页面复制一套颜色、圆角和阴影；新增组件先消费语义令牌，再由当前皮肤解析表达。后台不跟随店铺皮肤改变工作流，但必须使用自己的统一表面、间距、焦点、状态和性能规则。

## 一、视觉层级

按用户 2026-10-02 对客服联系卡片的追加要求，服务时间与渠道列表之间、相邻联系方式之间、渠道列表与咨询说明之间使用一条 `1px solid var(--line-subtle)` 浅色阅读分隔线。线条由 `modals-and-support.css` 统一放在既有间距中，不增加卡片高度，不在末尾或缺失分组处画线；手机、电脑、经典及深色皮肤共用，不增加独立色值或皮肤覆盖。

1. 页面背景、内容表面、弱强调表面是最多三级底色；禁止为强调层级再套多层彩色边框。
2. 页面结构依靠留白、字号、字重、底色和轻阴影。装饰分割线仅用于表格行、选项卡或确有阅读分组需要的地方；页面边框、整宽横线和卡片轮廓线不作为默认布局工具。
   区块标题、数量行、评价表单标题及通用弹层标题默认不画分隔线；同一表面内需要逐行扫描的列表可使用统一的 `--line-subtle` 弱分隔线，末行不画线。已确认的手机商品详情仅在数量控件的操作段及三项服务事实之间使用 `--skin-divider` 弱竖线，不扩展到卡片或其他页面。已有留白足以区分的分组不重复添加横线。此规则应修改组件原始声明，并检查多条数据和空状态；不得用皮肤覆盖或多层底色替代结构修正。
3. `--line` 是普通输入、邮箱选择、数量控件等常态浅边界；统一由共享语义色输出，不使用强边界色作为默认线条。`--line-strong` 保留明确强调边界，`--focus` 用于键盘焦点，选中规格使用 `--accent`。`--skin-divider` / `--line-subtle` 是弱装饰分隔色。强边界与焦点继续保留 3:1 校验，不能把该强对比颜色套在所有常态控件和容器上。
4. 所有桌面页面的页眉、正文、页脚和固定操作栏对齐同一内容基准。背景与页眉表面铺满视口，内部内容居中且最大宽度 1280px，窄屏至少留 32px 安全边距；页眉滚动时保持可见。不使用外层窄幅页面框或两侧异色空白。1024px 边界检查不得出现横向溢出。

### 共享样式的所有权

- 全站装饰图标统一为透明线形图标，不添加背景色块、圆角框、描边框或阴影。图标外观与图形尺寸由 `styles/semantic-icons.css` 单独拥有：标题和状态图标 24px，服务入口 28px，空状态 32px；页面只摆放图标槽和文字，不再复制框架或缩小内部图形。所有保留皮肤使用同一配色算法：读取实际页面、卡片、弱底色及悬停表面，保持图标线条至少 3:1 的对比度；浅底加深、深底提亮，不为单个皮肤追加组件规则。手机、电脑及后台预览使用同一共享色板。实际按钮、焦点、头像、商家图片及数量提示保持各自语义。

- 商品详情的购买摘要在手机与电脑上均按“商品名称、价格与库存、商品标签”排列；名称必须是结构上的第一项，不使用 CSS 排序补救。完整商品描述只在下方商品详情展示，购买摘要不再重复正文。
- 手机商品详情首图使用铺满页面左右的 1:1 正方形容器，外侧不留白、不设圆角；返回和分享按钮叠在首图上。购买摘要及下方正文仍按内容边距排列，商品主体沿用 `contain` 完整展示。
- 商品详情的购买数量行左侧为标签、右侧为共享 `QuantityControl`，按内容宽度靠右排列，不用 `width: 100%` 或弹性中列拉长选择器。沿用两侧各 44px 的触控按钮和至少 32px 的数字区域，常规数量总宽约 122px；多位数量按内容自然增宽。手机、电脑及各皮肤共用此布局，保留浅色分隔、焦点和库存禁用状态。
- 网格商品统一使用 `ProductCard` 与 `styles/product-card.css`，保留较小的 `--skin-control-radius`。横排商品统一使用 `ProductRow` 与 `styles/product-row.css`；商品行取消独立底色和外框，背景透明，图片四角使用 `--skin-media-radius` 圆角；横向排列时，相邻商品使用一条 `--skin-divider` 浅色阅读分隔线。横排文字列不额外添加上下内边距，让名称与价格区分别对齐方图上下边缘，避免图片下方出现额外白边；极窄列仍允许完整价格与库存独占下方一行，文字与价格区域同样不设独立底色或外侧内边距。图片保持 1:1 与 contain，不裁切商品。页面只决定列数、容器间距和排列，不重新声明卡片内部的边距、媒体圆角、标题高度、价格或库存样式。禁止恢复首页、分类页各自覆盖同一张商品卡的选择器链。
- 结账与确认购买的商品行统一归 `styles/checkout-items.css` 管理。手机、窄屏和电脑尺寸在该文件收敛；禁止 Tailwind 页面映射、桌面样式、皮肤样式分别用强制宽高覆盖同一张图。交付说明是辅助信息，不使用铺满文字列的成功状态底色。
- 手机与电脑购物车、商品详情、确认购买的数量选择共用 `QuantityControl` 和 `styles/quantity-control.css`。减号、数值、加号共用一个有清晰边界的外框，默认按钮为 44px。按 2026-10-01 用户要求，手机购物车使用组件内的紧凑规格：加减按钮 24px 宽、32px 高，数值至少 24px 宽，整体单数字时约 74px 宽；价格与数量固定同一行，完整支持 `55,555.55`，379px 以下把这一行扩展到图片和文字两列的总宽度。页面只负责摆放，不再分别覆盖内部尺寸、背景、边框和焦点。库存限制、加载禁用、数量为一时购物车删除行为仍由各调用方决定。

- 标题与同一行的数量、副标题使用共享基线对齐规则。商品价格与库存对齐基线；后台数值采用等宽数字，便于扫描与比较。

- 固定页眉优先使用不透明语义表面，不依赖滚动背景模糊。动效只指定实际需要变化的属性，后台导航也不得使用 `transition-all`。
- 语言和币种选项优先使用带标签的原生单选控件，保留方向键、焦点和禁用行为。弹窗完成初始聚焦后才能开始键盘验收；关闭后归还原触发器焦点。

## 三、后台和客户端只认一个配置源

- 前后台使用同一个 `StorefrontSemanticPalette` 和 `StorefrontSkinTreatment` 解析结果。后台的真实客户端 iframe 是验收主入口；离线示例只解释视觉规则，不得使用另一套硬编码色板。

- 装修区块自定义强调色只装饰该区块的图片、文案或图形，不能覆盖表单按钮、导航、价格、焦点等全局界面语义；全局控件只消费当前皮肤的语义色。

### 颜色分配与例外
