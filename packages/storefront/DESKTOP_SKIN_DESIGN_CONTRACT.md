# 全站三皮肤与体验设计契约

这份契约约束同一套电脑端组件如何表现为“经典 / 新中式 / 新锐科技极简”。皮肤只改变视觉语言，不改变商品、分类、购物车、支付或后台装修内容。手机首页轮播按用户要求采用文字叠图，公共顶部和分类区域按统一规格整理，其它手机结构保留；电脑端从 1024px 开始启用。这份规则本身不代表线上验收；发布状态必须由 CI、部署与真实店铺验收证据单独确认。

## 零、两层规则

全站只允许两层设计规则。第一层是所有皮肤、前台和后台必须遵守的体验基础：内容宽度、安全边距、阅读行宽、触控目标、焦点、状态反馈、媒体比例、动效预算和首屏体积预算。第二层是皮肤表达：页面与表面颜色、强调色、标题字体、圆角幅度和阴影气质。

皮肤不得改变导航位置、信息顺序、按钮含义、表单结构、加载逻辑或数据来源。禁止为单个页面复制一套颜色、圆角和阴影；新增组件先消费语义令牌，再由当前皮肤解析表达。后台不跟随店铺皮肤改变工作流，但必须使用自己的统一表面、间距、焦点、状态和性能规则。

### 样式归属与防覆盖门禁

| 所属层             | 职责                                                                    | 禁止事项                                                                           |
| ------------------ | ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 语义色板／皮肤适配 | 解析颜色、字体、圆角、阴影及根级令牌别名                                | 用皮肤 ID 的后代选择器直接修改组件；改写 Tailwind 全局色阶；添加页面布局或断点规则 |
| 共享组件           | 在原组件 CSS 或工具类源中消费令牌，定义正常、选中、悬停、禁用、焦点状态 | 在皮肤文件再复制表面和控件规则；依赖 `!important` 或提高皮肤选择器优先级修复冲突   |
| 页面／响应式布局   | 决定列数、阅读宽度、外侧留白及手机／电脑排列                            | 重定义组件内部颜色、媒体比例或重复的容器边框                                       |
| 按需加载模块       | 只影响其拥有的页面、组件和明确的共同消费者                              | 把分类导航等公共元素放入账户等无关页面的懒加载样式                                 |

- 修复固定白底、固定状态色或半径时优先改原始声明，包括工具类映射；不能在皮肤下用 `.bg-white`、`.text-slate-*` 等选择器二次染色。
- 皮肤身份选择器只能定义根级 CSS 变量。`skin-system.spec.ts` 同时检查前台源和实际共用的 `storefront-content-plugin/src/shared`，防止跨包组件重新引入皮肤覆盖。
- 皮肤生命周期检查必须覆盖经典、新中式、科技极简往返切换和卸载清理；浏览器检查必须包含首次进入分类页，以及连续进入账户、订单、工具页再返回分类后的计算样式一致性。
- 独立工具文档必须初始化共享语义令牌，不能假设外层商城 CSS 会跨文档继承；不得为视觉改动扩展会话或跨域授权协议。

动效只用于解释状态变化，优先使用 `transform` 与 `opacity`，普通反馈控制在 120–180ms，强调反馈不超过 240ms；禁止 `transition: all`。用户选择减少动态效果时必须即时完成状态变化。视觉滤镜、模糊和阴影不能成为列表滚动的持续计算负担。

构建体积与性能预算是防退化上限，不是可用额度或增长目标。新增改动原则上不得把产物继续推向上限；确需提高预算时，必须记录原因，并证明删除、复用或拆包不足以安全解决问题。

## 一、视觉层级

1. 页面背景、内容表面、弱强调表面是最多三级底色；禁止为强调层级再套多层彩色边框。
2. 页面结构依靠留白、字号、字重、底色和轻阴影。客户端所有页面均禁止使用装饰性分隔线，包括标题下划线、表格／列表行线、模块之间的横线和纵线。通过间距、字号、字重及语义底色区分信息层次；输入、选中、焦点和复合数量／区间控件的功能性边界保留。页面边框、整宽横线和卡片轮廓线不作为默认布局工具。
   区块标题、数量行、评价表单标题及通用弹层标题默认不画分隔线；已有表面和留白足以区分的评价列表、账户分组，不再重复添加横线。此规则应修改组件原始声明，并检查多条数据和空状态；不得用皮肤覆盖、末行取消边框或把线条调淡来替代修正。
3. `--line` / `--skin-divider` 用于需要清晰边界的控件，`--focus` 用于键盘焦点。保留这些令牌不代表允许内容区添加装饰分隔线；控件边框色不能套在所有容器上。
4. 所有桌面页面的页眉、正文、页脚和固定操作栏对齐同一内容基准。背景与页眉表面铺满视口，内部内容居中且最大宽度 1280px，窄屏至少留 32px 安全边距；页眉滚动时保持可见。不使用外层窄幅页面框或两侧异色空白。1024px 边界检查不得出现横向溢出。

### 页眉与首屏间距归属

- 所有子页面复用 `storefront-ui/page-shell.tsx` 的 `SubHeader` / `Subpage`；桌面页眉高度与账户页显隐由 `styles/subpage-content.css` 单独拥有。禁止页面复制页眉或补固定高度、导航高度占位。
- 顶部导航在正常文档流中占位一次；页面不再额外预留 72px。桌面子页标题按内容自然撑高，账户页由侧栏标识目的地，无桌面操作时整个页眉不占空间。
- 页眉中的移动端操作通过 `actionVisibility` 显式声明；DOM 中存在隐藏按钮不能作为预留一行的依据。地址选择等真正的桌面操作保留，手机端继续显示返回和标题。
- 骨架、错误和空状态遵守相同首屏规则。浏览器检查读取首个内容区与账户侧栏的真实坐标，覆盖三套皮肤和 1024px 边界；源代码合同阻止复制页眉及分散定义页眉尺寸。

## 二、皮肤角色和组件规则

| 角色       | 经典                                                 | 新中式                             | 新锐科技极简                         |
| ---------- | ---------------------------------------------------- | ---------------------------------- | ------------------------------------ |
| 页面与表面 | 清爽浅灰 / 白                                        | 暖纸色 / 米白                      | 深墨色 / 冷黑蓝                      |
| 身份与强调 | 商家原始品牌色保留为身份色，界面强调色自动派生安全值 | 墨青导航选择、陶红主操作与暖白表面 | 浅墨青导航选择、紫色主操作与冷色层次 |
| 标题字体   | 系统无衬线                                           | 中文宋体气质，仅标题               | 系统无衬线                           |
| 圆角       | 卡片 16、主视觉 20、控件 10px                        | 卡片 14、主视觉 18、控件 8px       | 卡片 16、主视觉 20、控件 10px        |
| 层次       | 柔和中性阴影                                         | 更暖、更轻的阴影                   | 深色低明度阴影                       |

按钮分主、次、文字三级：同一页面、弹窗或任务焦点只保留一个视觉最强的主操作；后台必要的并列业务操作可以保留，但除非其中一个是明确下一步，否则使用次级或文字层级。主按钮用 `accent / onAccent`，次按钮用弱表面和主文字，文字按钮不再额外画框。可点击控件保持可辨认的悬停、禁用和键盘焦点状态；正文对比度至少 4.5:1，关键控件及焦点至少 3:1。导航选择与操作强调为独立语义；深色皮肤反转导航选中底色与文字明度，不能直接复制浅色皮肤的深选中色。

商品列表媒体框固定 1:1，图片 `contain`，不裁掉商品主体；媒体与卡片共用外圆角，不在图片外再嵌套一圈装饰边。详情长图保持自身比例；电脑首页轮播统一采用 3:1 容器、最小高度 320px，图片 `contain` 并靠右完整展示，空余空间沿用该广告的文案底色。图片尺寸不得改变轮播、右侧入口及后续模块的位置，后台草稿预览必须使用相同的容器规则。按用户要求，手机首页轮播也将标题、说明、卖点和主操作叠放在图片上，采用 280px 最小高度；营销图片用 `cover` 填充，允许响应式裁切，文字区域使用原广告配色的渐变衬底，长文案可撑高容器，不能裁掉按钮。商品图片和详情长图不受该营销例外影响。图片不能替代标题与文案。卡片标题、属性、价格和库存形成稳定的信息顺序；缺图使用可辨认的占位，不留下空洞。

手机个人中心的 `ACCOUNT_HERO` 图片仅作为整张账户卡片的装饰背景，允许 `cover` 裁切。头像、姓名、资料入口、余额和优惠券必须叠放在同一背景上；高度由实际内容与内边距决定，禁止把背景图放入文档流形成独立大图。背景衬底与文字使用共享语义表面和文字色，登录与未登录状态、缺图回退均保持可读。

### 共享样式的所有权

- 商品详情的购买摘要在手机与电脑上均按“商品名称、价格与库存、商品标签”排列；名称必须是结构上的第一项，不使用 CSS 排序补救。完整商品描述只在下方商品详情展示，购买摘要不再重复正文。
- 手机商品详情首图使用铺满页面左右的 1:1 正方形容器，外侧不留白、不设圆角；返回和分享按钮叠在首图上。购买摘要及下方正文仍按内容边距排列，商品主体沿用 `contain` 完整展示。
- 网格商品统一使用 `ProductCard` 与 `styles/product-card.css`；横排商品统一使用 `ProductRow`。页面只决定列数、容器间距和排列，不重新声明卡片内部的边距、媒体圆角、标题高度、价格或库存样式。禁止恢复首页、分类页各自覆盖同一张商品卡的选择器链。
- 结账与确认购买的商品行统一归 `styles/checkout-items.css` 管理。手机、窄屏和电脑尺寸在该文件收敛；禁止 Tailwind 页面映射、桌面样式、皮肤样式分别用强制宽高覆盖同一张图。交付说明是辅助信息，不使用铺满文字列的成功状态底色。
- 手机与电脑购物车、商品详情、确认购买的数量选择共用 `QuantityControl` 和 `styles/quantity-control.css`。减号、数值、加号共用一个有清晰边界的外框，按钮为 44px；页面只负责摆放，不再分别覆盖内部尺寸、背景、边框和焦点。库存限制、加载禁用、数量为一时购物车删除行为仍由各调用方决定。
- 电脑首页采用 8:4 主视觉与快捷入口，保障条横跨下方。营销图片、文案和模块数据与移动端同源；图片完整展示，文字放在皮肤语义表面上。图文确需叠放时，按文字区域检测对比度，复杂图片用局部底色保护文字，不覆盖或调暗整张图片。首页精选商品保留标题、数量及现有展示控件，一级分类导航归商品页面，精选区不再复制一套分类导航或分类筛选状态；后台配置的营销／快捷入口不受此约束影响。工具页布局应适应商家启用任意数量的服务。
- 手机营销主操作至少 44px 高，内容允许自然撑高主视觉；不为了固定高度挤压触控区或裁去后台文案。按用户最新验收要求，首页轮播的标题、说明和主按钮叠放在营销图片上，前台与后台手机预览共用响应式排版，不再使用图片下方的独立文案面板。营销图可按主视觉容器裁切；商品图仍保持完整展示。账户的金额、数量优先清晰排列，不在父面板内重复堆叠装饰卡片。
- 页面背景、内容表面、浮层、媒体占位和状态色都消费共享语义色；阴影强度由 `StorefrontSkinTreatment` 管理。皮肤表达不能通过给每个控件增加渐变、轮廓和发光来叠加层级。
- 2FA 工具的查询区最多保留一层内容表面；临时／加密状态、查询结果、展开表单和空状态保持平面排版，不在父区块内再次添加圆角卡片或虚线框。账号列表不套外层卡片，每个账号只保留一层表面，动态码行不再嵌套色块。桌面布局不得重新给所有子区块统一套框；输入边界、焦点和独立操作浮层仍保留。
- `control-surfaces.css` 只作用于真实店铺与其浮层，不污染预览工具栏或后台。预览控件与被预览页面是两个独立作用域。
- 导航选中、排序选中属于状态，不等同于主操作。使用独立的 selection / selection-foreground 深浅配对和勾选等非颜色标识；悬停使用 interaction-hover / interaction-ink，按下使用 interaction-pressed，主操作继续使用 accent。页眉搜索、账户入口默认次级，避免与页面购买、提交或保存争抢视觉优先级。
- 标题与同一行的数量、副标题使用共享基线对齐规则。商品价格与库存对齐基线；后台数值采用等宽数字，便于扫描与比较。
- 页面标题栏的表面由共享标题组件消费皮肤令牌，桌面布局可将其融入页面；不得用高优先级皮肤选择器重新覆盖底色或阴影。交易容器的圆角与表面由组件拥有，桌面商品表格内部只用阅读分隔，不重复套圆角、外框和阴影。验收同时覆盖直接打开页面与站内导航进入页面。
- 固定页眉优先使用不透明语义表面，不依赖滚动背景模糊。动效只指定实际需要变化的属性，后台导航也不得使用 `transition-all`。
- 语言和币种选项优先使用带标签的原生单选控件，保留方向键、焦点和禁用行为。弹窗完成初始聚焦后才能开始键盘验收；关闭后归还原触发器焦点。

上述所有权由组件测试、共享样式契约和真实浏览器回归共同约束。`skin-system.spec.ts` 全量扫描客户端 CSS、Tailwind 样式映射和组件类名，禁止重新引入单边装饰线、`divide-x/y` 和细线伪元素；功能性控件例外必须有明确用途，不能按页面或皮肤放行。文本、价格、币种、交付方式、库存与后台配置仍来自原有业务数据，视觉重构不得替换它们。

对比度门禁必须包含主按钮的默认和悬停状态，不能仅验证初始色板。预览皮肤、模拟会话与导航桥接以 iframe 本次加载为生命周期，不能在站内路由去掉查询参数后失效；验收必须包含连续切页以及同一账户页手机／电脑宽度往返切换。

### 已确认布局的保留与工作区整合

视觉优化必须先核对当前预览服务对应的工作区和构建产物。迁移工作区时，除比较提交外，还必须盘点原预览工作区的未提交页面改动；不能只凭新工作区的构建通过就宣布设计承接完整。

首页图上文案、账户顶部整合、订单导航与搜索同排、购物车商品区与摘要区、地址和足迹工具栏属于已确认的布局基线。恢复旧设计时只迁移对应结构和样式，不覆盖后来新增的业务、安全、可读性和性能修复。购物车在宽电脑端使用右侧摘要，窄电脑端可将摘要放到表格下方，手机仍保留底部结算操作。相关浏览器门禁检查图文覆盖关系、摘要位置和按钮数量，而不只检查页面是否加载。

## 三、后台和客户端只认一个配置源

- 保留 `classic`、`modern-oriental`、`neo-minimalist` 三个 ID、现有按店铺保存接口与数据库字段。后台草稿预览不发布；保存后客户端读取当前店铺 ID 生效。
- 前后台使用同一个 `StorefrontSemanticPalette` 和 `StorefrontSkinTreatment` 解析结果。后台的真实客户端 iframe 是验收主入口；离线示例只解释视觉规则，不得使用另一套硬编码色板。
- 商家品牌色原值不改写。经典皮肤自动派生可读的按钮和文字色；区块自定义颜色需先通过对比度审计，风险在后台提示。
- 装修区块自定义强调色只装饰该区块的图片、文案或图形，不能覆盖表单按钮、导航、价格、焦点等全局界面语义；全局控件只消费当前皮肤的语义色。
- 装修区块、导航、商品、图片和文案仍只保存一次，手机与电脑消费同一份数据。电脑端不得写入演示商品、固定价格、假购物车数或固定币种。
- 核心品类双卡片的内容、跳转和楼层位置由当前店铺后台保存的配置决定。实际首页复用共享 `HomeDualCategoryShowcase`，不得在页面另建同名实现。
- 核心品类使用 `publishedContentItems`：按已保存的卡片位置排序，过滤停用项，展示前两张。Shop API、发布检查、编辑器预览与楼层结构预览使用同一规则；备用卡片不影响前两张的发布，后台仍保留完整草稿。

## 四、七类页面的收敛顺序

1. 发现：首页、分类、搜索、闪购、推荐。首页 Bento 和商品网格先在三皮肤确认，再推广分类筛选、排序和分页。
2. 商品：双栏、1:1 主图、规格与购买动作，详情长图自然比例。
3. 交易：购物车、确认购买、结账、支付、完成；主内容和摘要清晰分列，状态与校验沿用现有业务逻辑。
4. 账户：固定侧栏与内容工作区，订单、物流、地址、安全、收藏、足迹、通知、券、返利、评价共用卡片和列表规则。
5. 认证：登录、注册、验证、找回与重置，共用电脑端双栏，不放大手机表单。
6. 工具：服务中心、图片工坊、2FA、邮件查询，按工作台布局呈现操作和结果。
7. 内容：公告、客服、协议、404，保持统一阅读宽度和清晰空状态。

商业服务页的手机排版使用单列横向图标与文字；入口、客服均消费同一份后台配置。其它手机页面保留原有结构与功能。按最新验收反馈，手机端共用的首页、分类、搜索、商品、购物车、结账、订单、地址与账户装饰性线框改为表面层次与留白；输入、选中、焦点和数量控件的功能性边界保留，且仅在 1024px 以下生效。

公共顶部采用统一几何规格：手机端的 `.topbar`、`.mobile-page-header` 和 `.search-header` 均为 52px 高，控件为 44px 高，垂直内边距为 4px；普通页面左右边距为 16px。电脑端公共导航为 72px 高，1024–1180px 的搜索入口收为单行图标按钮，进入搜索页不得导致导航高度跳变。营销首屏、页面标题与工具工作区内容按各自内容排列，不参与顶部导航高度统一。

首页、我的和商业服务的手机品牌顶部必须共用 `MobilePageHeader`，以首页原有 `.home-topbar`、`.brand`、`.topbar-actions` 和 `NoticeButton` 为唯一视觉实现。不得另建小 Logo、描边胶囊、单独通知按钮或另一套分隔线；页名和点击行为由组件参数决定。语言货币入口与通知按钮的默认、悬停、按下状态统一由 `brand-shell.css` 的公共 `.topbar` 控件规则消费皮肤令牌，不能再按页面重复覆盖。

手机分类区共用同一 `--surface` 底色，分类行高 96px、上下内边距 12px、图标尺寸 44px；“全部分类”与普通入口保持图标和文字对齐，不单独铺底色。中文分类沿用等宽可滚动槽位，英文长名称允许两行。搜索、分类、排序、商品保持同一 16px 左右基线，排序条高 52px、上下各留 12px，强调色只用于选中状态和主要操作。搜索结果页沿用相同的控件高度、外侧边距和排序间距。

手机二级分类侧栏使用 `--soft` 底色，选中项与右侧商品区域共用 `--surface`，两侧零间隙、零分隔线，形成连续背景。不能再将右侧改为页面底色使分区变淡；键盘焦点向按钮内侧显示，避免侧栏裁掉轮廓形成上下两条线。

手机账户的六个订单入口使用 `AccountOrderCarousel`：正方形卡片单行排列，图标在上、文字在下，角标沿用真实订单数量。窄屏通过原生横向滚动和左右按钮浏览，按钮每次移动一个入口；到达边界时禁用对应按钮，全部入口能显示时隐藏滑动控件。滚动不能带动整页横向溢出，点击卡片继续打开原来的订单状态、评价或售后入口，并尊重减少动态效果偏好。

电脑订单页的筛选、搜索与内容区域由 `.orders-page` 网格统一管理 24px 横纵间距；窄电脑宽度下搜索换行后沿用相同间距。订单列表、售后列表和空状态不再自行叠加顶部内外边距。订单空状态由订单页样式独立拥有，内容在表面内垂直居中，通用页面和账户页面的空状态规则不再覆盖它。

手机分类页恢复原有视口框架：搜索与一级分类保持顶部可见，商品和二级分类在各自区域原生滚动，排序条在商品区内吸顶且不随滚动方向隐藏。商品区域高度扣除顶部和底部导航，末尾商品与加载更多入口必须可达；分页观察器使用实际商品滚动容器，电脑端沿用页面滚动。

每一类都应检查正常、空、加载、错误、禁用、弹窗、悬停与键盘焦点。验收三套皮肤的真实组件与真实店铺数据，检查 320、390、1023、1024、1440、1920、2560px；手机端除商业服务页、首页轮播文字叠图与上述共用表面修复外不得改变结构和业务交互。自动门禁通过不等于商家真实数据人工验收，更不等于已经部署上线。
## 发布修复不得替换已确认设计

独立演示预览的样式不得覆盖本契约已集成的视觉规则。首页宽电脑端继续采用 8:4 主视觉与右侧快捷入口，保障条在其下方；窄电脑端按既有断点自然纵排。页眉表面铺满视口，内部对齐最大 1280px 内容基准，电脑端商品媒体与卡片共用外圆角，手机商品详情主图按最新要求以正方形铺满左右且不使用圆角。订单缩略图固定 68px、账户空页眉不占空间、优惠券工作区和客服真实 FAQ 搜索等缺陷修复继续保留。修改设计选择前必须核对本契约、用户最新指令和实际预览，不得为错误实现改写验收目标。
