# 全站三皮肤与体验设计契约（预览阶段）

这份契约约束同一套电脑端组件如何表现为“经典 / 新中式 / 新锐科技极简”。皮肤只改变视觉语言，不改变商品、分类、购物车、支付或后台装修内容。手机端保留现有结构；电脑端从 1024px 开始启用。当前处于本地预览与回归阶段，不能据此宣布线上验收通过。

## 零、两层规则

全站只允许两层设计规则。第一层是所有皮肤、前台和后台必须遵守的体验基础：内容宽度、安全边距、阅读行宽、触控目标、焦点、状态反馈、媒体比例、动效预算和首屏体积预算。第二层是皮肤表达：页面与表面颜色、强调色、标题字体、圆角幅度和阴影气质。

皮肤不得改变导航位置、信息顺序、按钮含义、表单结构、加载逻辑或数据来源。禁止为单个页面复制一套颜色、圆角和阴影；新增组件先消费语义令牌，再由当前皮肤解析表达。后台不跟随店铺皮肤改变工作流，但必须使用自己的统一表面、间距、焦点、状态和性能规则。

动效只用于解释状态变化，优先使用 `transform` 与 `opacity`，普通反馈控制在 120–180ms，强调反馈不超过 240ms；禁止 `transition: all`。用户选择减少动态效果时必须即时完成状态变化。视觉滤镜、模糊和阴影不能成为列表滚动的持续计算负担。

构建体积与性能预算是防退化上限，不是可用额度或增长目标。新增改动原则上不得把产物继续推向上限；确需提高预算时，必须记录原因，并证明删除、复用或拆包不足以安全解决问题。

## 一、视觉层级

1. 页面背景、内容表面、弱强调表面是最多三级底色；禁止为强调层级再套多层彩色边框。
2. 页面结构依靠留白、字号、字重、底色和轻阴影。装饰分割线仅用于表格行、选项卡或确有阅读分组需要的地方；页面边框、整宽横线和卡片轮廓线不作为默认布局工具。
3. `--line` / `--focus` 是输入框、选中规格、键盘焦点等需要清晰边界的控件色；`--skin-divider` 才是弱装饰分隔色。不能把 3:1 的控件边框色套在所有容器上。
   页面内容表面由 `styles/control-surfaces.css` 统一收口：默认无装饰外框，使用表面色、留白和皮肤阴影分层；强制高对比模式恢复必要边界。
4. 所有桌面页面的页眉、正文、页脚和固定操作栏对齐同一内容基准。背景与页眉表面铺满视口，内部内容居中且最大宽度 1280px，窄屏至少留 32px 安全边距；页眉滚动时保持可见。不使用外层窄幅页面框或两侧异色空白。1024px 边界检查不得出现横向溢出。
5. 手机端页面使用单一 `--page-section-inset` 横向基准，默认解析为 `--experience-page-gutter-mobile` 16px。页标题、搜索、分类、排序、内容卡片、商品区和页脚不得再各自定义不同外边距；单个商品自适应为满宽横向卡片，避免半屏空置。
6. 桌面端购物车使用“商品工作区 + 单一结算摘要”结构。优惠券属于结算决策，不得作为独立通栏重复占据页面；合计与结算按钮跟随摘要而不是固定在视口底部。移动端继续使用轻量优惠入口与底部固定主操作。
7. 桌面端账户二级页由左侧账户导航承担当前位置识别，内容区不得重复显示同名返回标题行；存在新增、清空等真实页面操作时，仅保留操作控件。移动端仍保留返回按钮与页面标题。
8. 桌面端商品结果数量较少时也要维持桌面信息密度。单个商品自动切换为受控宽度的横向结果卡，图片仍保持 1:1 且 `contain`；不将手机竖卡孤立放在大片空白中，也不把单卡拉伸为整行巨型宣传位。
9. 桌面端工具页使用“主任务工作区 + 参数/结算区”的工作台结构，标签页只承担视图切换，不用整宽横线切断页面。表单输入保留功能性边界，容器依靠表面、留白和阴影分层。

## 二、皮肤角色和组件规则

| 角色 | 经典 | 新中式 | 新锐科技极简 |
| --- | --- | --- | --- |
| 页面与表面 | 清爽浅灰 / 白 | 暖纸色 / 米白 | 深墨色 / 冷黑蓝 |
| 身份与强调 | 商家原始品牌色保留为身份色，界面强调色自动派生安全值 | 固定朱红强调、克制暖色层次 | 固定紫色强调、冷色层次 |
| 标题字体 | 系统无衬线 | 中文宋体气质，仅标题 | 系统无衬线 |
| 圆角 | 卡片 16、主视觉 20、控件 10px | 卡片 14、主视觉 18、控件 8px | 卡片 16、主视觉 20、控件 10px |
| 层次 | 柔和中性阴影 | 更暖、更轻的阴影 | 深色低明度阴影 |

按钮分主、次、文字三级：同一页面、弹窗或任务焦点只保留一个视觉最强的主操作；后台必要的并列业务操作可以保留，但除非其中一个是明确下一步，否则使用次级或文字层级。主按钮用 `accent / onAccent`，次按钮用弱表面和主文字，文字按钮不再额外画框。可点击控件保持可辨认的悬停、禁用和键盘焦点状态；正文对比度至少 4.5:1，关键控件及焦点至少 3:1。

商品列表媒体框固定 1:1，图片 `contain`，不裁掉商品主体；媒体与卡片共用外圆角，不在图片外再嵌套一圈装饰边。详情长图保持自身比例。主视觉图片可按营销横幅裁切，但图片不能替代标题与文案。卡片标题、属性、价格和库存形成稳定的信息顺序；缺图使用可辨认的占位，不留下空洞。

## 三、后台和客户端只认一个配置源

- 保留 `classic`、`modern-oriental`、`neo-minimalist` 三个 ID、现有按店铺保存接口与数据库字段。后台草稿预览不发布；保存后客户端读取当前店铺 ID 生效。
- 前后台使用同一个 `StorefrontSemanticPalette` 和 `StorefrontSkinTreatment` 解析结果。后台的真实客户端 iframe 是验收主入口；离线示例只解释视觉规则，不得使用另一套硬编码色板。
- 商家品牌色原值不改写。经典皮肤自动派生可读的按钮和文字色；区块自定义颜色需先通过对比度审计，风险在后台提示。
- 装修区块自定义强调色只装饰该区块的图片、文案或图形，不能覆盖表单按钮、导航、价格、焦点等全局界面语义；全局控件只消费当前皮肤的语义色。
- 装修区块、导航、商品、图片和文案仍只保存一次，手机与电脑消费同一份数据。电脑端不得写入演示商品、固定价格、假购物车数或固定币种。

## 四、七类页面的收敛顺序

1. 发现：首页、分类、搜索、闪购、推荐。首页 Bento 和商品网格先在三皮肤确认，再推广分类筛选、排序和分页。
2. 商品：双栏、1:1 主图、规格与购买动作，详情长图自然比例。
3. 交易：购物车、确认购买、结账、支付、完成；主内容和摘要清晰分列，状态与校验沿用现有业务逻辑。
4. 账户：固定侧栏与内容工作区，订单、物流、地址、安全、收藏、足迹、通知、券、返利、评价共用卡片和列表规则。
5. 认证：登录、注册、验证、找回与重置，共用电脑端双栏，不放大手机表单。
6. 工具：服务中心、图片工坊、2FA、邮件查询，按工作台布局呈现操作和结果。
7. 内容：公告、客服、协议、404，保持统一阅读宽度和清晰空状态。

商业服务页的手机排版使用单列横向图标与文字；入口、客服均消费同一份后台配置。其它手机页面保留原有结构与功能。按最新验收反馈，手机端共用的首页、分类、搜索、商品、购物车、结账、订单、地址与账户装饰性线框改为表面层次与留白；输入、选中、焦点和数量控件的功能性边界保留，且仅在 1024px 以下生效。

每一类都应检查正常、空、加载、错误、禁用、弹窗、悬停与键盘焦点。验收三套皮肤的真实组件与真实店铺数据，检查 320、390、1023、1024、1440、1920、2560px；手机端除商业服务页与上述共用表面修复外不得改变结构和业务交互。自动门禁通过不等于商家真实数据人工验收，更不等于已经部署上线。
