## 审计结论与重构结果

原有后台具备紧凑布局、主题、路由标签、错误归一化和权限机制，但页面分别制定读取与刷新方式，缺少完整的统一行为契约。

| 问题                                                  | 本次公共机制                                                                             |
| ----------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 页面分别设置缓存策略，切回或轮询出现额外读取          | Apollo 唯一缓存，公共资源身份、时效、活动状态、正在进行的刷新合并                        |
| 商品详情覆盖列表所需 customFields，切回列表缓存不完整 | 生产和验收共用 createAdminCache，合并未选字段，保留显式 null 的覆盖语义                  |
| 商品列表原手工刷新遗漏成本等附属资源                  | 本页统一刷新及配置、主列表、依赖当前 ID 资源的分阶段读取；回调和按钮使用同一入口         |
| 刷新把已加载内容变成整页加载或失败占位                | 保留同一身份下的数据，区分首载、更新中、已有数据更新失败和无数据失败                     |
| 隐藏标签和断网仍有后台周期任务                        | 查询与活动定时器统一消费页面活动、窗口可见性及联网状态                                   |
| 写入期间旧读取可能消耗新的失效标记                    | 失效代次保留；写入刷新等待旧页面读取结束后再更新失效数据                                 |
| 刷新覆盖未保存输入或暂时取消离开保护                  | 版本化草稿、独立于 loading 的 dirty 保护、冲突提示、离开确认；干净标签按最近使用顺序释放 |
| 写成功后读取失败被描述为操作失败                      | 独立读取回执及统一 refreshAfterAdminWrite；不重放写入                                    |
| 控件尺寸、搜索、恢复方式分散                          | AdminControls、SearchInput、防抖与输入法、页面状态条、页面错误边界、版本恢复草稿保护     |

统一规则：[LOADING_REFRESH_INTERACTION_STANDARD.md](./LOADING_REFRESH_INTERACTION_STANDARD.md)。
执行方案：[LOADING_REFRESH_REFACTOR_PLAN.md](./LOADING_REFRESH_REFACTOR_PLAN.md)。
后续开发约束写入包内 AGENTS.md，根规则与客户端源码未修改。
