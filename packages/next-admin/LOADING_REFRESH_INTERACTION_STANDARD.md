# 管理后台统一加载、刷新与交互标准

适用范围：管理后台所有业务路由、编辑页、弹窗、内嵌面板和后台扩展。
本轮性能候选基于线上已核对的 eeed0dfdc380512822f961e31f5e74d0e88ff736；本地验证与生产发布分别记录。

## 用户操作对应的数据行为

| 操作                       | 统一行为                                                                             |
| -------------------------- | ------------------------------------------------------------------------------------ |
| 首次进入页面               | 页面壳保持可用；缺少业务数据的区域显示加载状态；失败提供重试；结果为空显示业务空状态 |
| 切回标签                   | 保留筛选、分页、滚动和输入；新鲜资源直接使用缓存，过期或失效资源更新                 |
| 本页刷新                   | 覆盖本页已启用资源及公共配置，配置、主列表、依赖当前 ID 的附属数据分阶段更新         |
| 多次点击刷新               | 同一资源和同一页面的进行中刷新合并，不多发请求                                       |
| 后台更新                   | 保留同一查询条件的可用内容，显示更新状态；失败保留内容并标明失败                     |
| 筛选和实体变化             | 新查询身份，新条件下不可展示旧实体或旧筛选结果作为当前结果                           |
| 隐藏标签、窗口或离线       | 暂停自动读取和周期任务；恢复后更新失效或过期资源                                     |
| 业务写入成功               | 使相关资源域失效，活动页更新；隐藏页恢复时再读取；不重放写操作                       |
| 服务端更新与未保存输入并存 | 保留草稿，提示冲突；明确放弃草稿再读取后才可继续保存                                 |
| 关闭标签或加载新版本       | 沿用草稿确认；提交中的写入返回前禁止主动加载新版本                                   |
| 页面渲染异常               | 当前标签显示恢复入口，导航和其他页面保留可用                                         |

## 公共机制与边界

- Apollo 是唯一共享数据缓存。AdminQueryRuntime 只维护身份、所属页面、活动状态、时效、失效和进行中的刷新，不存业务数据副本。
- Runtime 按资源与页面发布状态变化；共享资源通知所有所属页面，公共配置通知活动页面。隐藏工作区取消状态订阅，恢复时读取当前快照，不建立全站广播订阅。
- 资源身份包括实际 GraphQL document、排序规范化变量、请求上下文及当前作用域版本。请求身份仅在内存中使用，不打印请求上下文或凭据。
- 列表、详情查询共同写入嵌套 customFields 时执行字段合并；显式 null 仍覆盖旧值。避免详情读取删除列表所需字段而触发切回后的重复加载。
- 配置默认 5 分钟、统计 1 分钟、普通数据 30 秒新鲜期。实时资源频率在 queryPolicy 统一声明；必要的业务轮询频率由查询选项声明，活动状态仍由公共适配器控制。
- 手动刷新执行已启用查询，不打开未启用弹窗查询。不自动重试业务写入。托管 GraphQL 读取超时为 45 秒；HTTP 健康读取另有自身取消与超时约束。
- Auth 会话入口与 AppShell 引导读取保留原有流程。AppShell 的经营模式显式读取用于更新导航配置；它不是业务列表的另一套缓存。
- 默认最多保留 8 个无未保存修改的页面，最近最少使用的干净页面可释放；脏页面额外保留。URL 中的筛选仍存在，超过缓存容量的干净页面可能重新挂载。
- useServerDraft 管理基线、当前草稿和服务端版本；已有 dirty-ID 表单必须登记公共离开保护，dirty 不与读取 loading 耦合。权限、价格、支付、库存和业务校验仍由原有接口执行。
- 草稿通过不可变更新产生新引用；相同基线与草稿引用复用 dirty 判断。商品行的派生数据依赖查询结果，不能随弹层、选中状态或后台状态通知反复遍历所有商品。
- 业务路由沿用 AppShell / TabbedOutlet 提供的 AdminPageWorkspace；独立业务入口同样接入公共工作区。扩展宿主提供加载、失败和局部重试，保留相邻面板的已加载内容与草稿。
- 导航意图立即预取对应路由；公共后台预取每个空闲时段只启动一个模块，当前页读取、隐藏窗口、离线与省流连接优先。取消预取队列后不继续启动后续模块。

## 页面与组件设计

- 导航、标签和页面主内容分别承担定位、任务连续性和业务操作；页面异常或读取失败不能占满整个应用。
- 同一任务一个视觉最强主操作。刷新、筛选和辅助操作使用次级强调。表格保持扫描密度、必要的横向滚动和稳定操作位置。
- 按钮、输入框、下拉框和文本域使用 AdminControls。桌面按钮至少 32px，文字输入至少 36px；触控环境至少 44px。保持主题、焦点环、禁用和忙碌状态。
- SearchInput 默认 250ms 防抖，中文组合输入结束、回车、清空和失焦立即提交；隐藏页面取消未提交的计时。
- 首次读取用 loading && !data 判断；不得把 Apollo 的原始 loading 改成假值。写入禁用状态继续消费真实 mutation loading。
- 统一状态条说明更新、断网和局部失败；局部业务错误显示明确原因及可执行重试。已加载内容不得在刷新时被整页加载占位替换。
- 延续现有语义颜色、间距、圆角、焦点及中性边框；动效只解释加载或状态，支持 reduced-motion。
- 短字段沿用 AdminField：手机 767px 以下标签上置；其余宽度下，字段自身宽度达到 20rem 时左标题、右控件，否则纵排。标题最多占 9rem，控件可收缩且保留触控尺寸。说明、校验信息跟随控件。文本域、上传与复杂编辑区保留 stacked；不根据整个浏览器宽度强迫窄弹窗或多列表单横排。
- 弹窗继续使用 AccessibleDialogSurface 的焦点与退出规则；敏感操作保留原有确认及权限验证。
- 需要 portal 的弹层使用 AdminOverlayPortal，并把遮罩与内容一起放入最近的 AdminOverlayHost。页面宿主随标签隐藏并保持草稿；全局确认使用应用宿主。帮助卡片沿用触发按钮的宿主，关闭所属标签时清理。只有最上层接收 Escape，模态弹层共享焦点限制和滚动锁。
- 大列表可使用 useVirtualRows，素材网格使用 AdminVirtualGrid；传入稳定的行身份、内容节点与实际滚动容器，保留服务端分页、选择、排序和草稿所有权。普通 20 行分页不强制窗口化；焦点所在行不能被卸载，离线仍能滚动已加载内容。商品表仅在超过 50 行时启用，素材超过 40 项时启用。
- AdminImage 复用公共 mediaDescriptor 的资源身份、版本、响应式候选与 sizes。不要另加图片 URL 规则或额外网络占位图；展示错误按资源身份隔离，换图可以恢复。

## 新功能接入和验收

1. 查询通过 useAdminQuery/useAdminLazyQuery；非 GraphQL 读取通过 useAdminReadResource。
2. 声明业务资源域。新增 mutation 根字段须核对 resourceDomains；写入后局部回读需要明确区分写入失败与读取失败。
3. 使用共享控件和页面状态。编辑表单不得直接用查询更新覆盖草稿。
4. 从本包执行 bun run check:feedback 与受影响单测；源码变化执行后台构建，有交互或布局变化执行对应浏览器场景。纯规则或检查工具变化使用定向规则测试，不默认增加全仓 CI 或后端/数据库矩阵。
5. 缓存、合并、隐藏轮询、超时和作用域隔离用实际 Apollo 测试；单元 mock 只证明业务渲染与回调。
6. 验收报告分开记录源码覆盖、单元测试、浏览器合成场景、生产环境和真实业务结果。

本地公共性能交互夹具：从本包启动 `PORT=5338 bun run dev`，打开 `/e2e/admin-layout/index.html?view=performance&light`。可验证 8 个干净页加 2 个脏草稿、隐藏页面 portal、嵌套确认与 Escape、作用域重挂载和 100 项素材窗口化；全部是合成数据，不代表真实账号、权限切换或业务写入验收。

## 自动门禁与例外管理

仓库根 AGENTS.md 引导所有后台任务读取本包 AGENTS.md 与本标准。现有 `bun run check:feedback` 自动调用 `scripts/audit-admin-interaction.mjs`；现有 `bun run build` 在编译前执行同一入口。违规时命令以非零状态退出，新增 src 目录不需要手工登记扫描清单。

| 自动检测项                                                        | 强制接入方式                                                                      |
| ----------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 直接导入 Apollo 读取 Hook，以及直接命名空间调用（含常见类型断言） | 业务读取改用 use-admin-query；只保留 Auth/AppShell 引导与公共适配器的指定文件例外 |
| 原生 button/input/select/textarea                                 | 使用 AdminControls；仅公共控件实现本身可使用原生元素                              |
| 直接 setInterval/window.setInterval/globalThis.setInterval        | 使用 useActiveInterval；仅公共活动状态 Hook 可创建周期任务                        |
| location.reload/window.location.reload                            | 业务刷新使用 refreshPage；新版本恢复沿用 build-recovery                           |
| 可解析的静态 gql mutation 根字段没有业务资源域                    | 完善生产资源域规则并验证受影响读取失效；门禁读取生产规则，不复制另一份映射        |

检查覆盖 src 的生产 JS/TS 文件，普通测试目录和 spec/test 文件排除。它不会证明数据身份、草稿保护、资源域语义或所有间接调用都正确；动态拼装文档和外部扩展须有运行时契约测试。不要为新业务复制例外、关闭检查、扩大白名单或抬高预算。公共能力不足时先完善公共层；确有例外时记录范围、位置、原因及定向回归，遵守上级权限规则。

## 新页面验收矩阵

以下场景按功能实际影响验收；不适用的场景写明原因。公共机制未变化时可复用对应机制的有效测试证据，新增业务接入仍要验证自身行为。

| 场景                               | 通过条件                                                    |
| ---------------------------------- | ----------------------------------------------------------- |
| 首次读取、空数据与失败             | 页面壳可用，加载/空态可区分，失败原因和重试明确             |
| 同条件刷新与连续点击               | 保留内容与输入，进行中请求合并，失败不伪装为成功            |
| 筛选、分页、中文组合输入与实体切换 | 提交时机符合公共搜索规则，新条件无旧实体结果串用            |
| 切回标签、隐藏窗口、离线与恢复     | 不活跃时停止自动任务，恢复按时效与失效状态读取              |
| 写入成功后回读失败                 | 成功写入只执行一次，反馈区分读取失败并仅重试读取            |
| 草稿、服务端版本变化、离开与关闭   | 未保存输入不被覆盖，冲突明确，离开确认不受后台 loading 影响 |
| Channel/权限作用域变化             | 新作用域没有旧业务数据，权限失效走原有权限处理              |
| 弹窗与扩展局部失败                 | 焦点和退出可用，未启用查询不读取，重试保留相邻草稿          |
| 桌面、手机、主题与键盘             | 任务主次清楚、列表可扫描、触控可用、标签焦点和语义配色一致  |

这些规则用于持续防止架构回退；新增业务仍需受影响测试与验收，不能以静态检查替代行为验证。

官方依据：[Apollo 缓存字段合并](https://www.apollographql.com/docs/react/caching/cache-field-behavior)、[Apollo 查询状态](https://www.apollographql.com/docs/react/data/queries)、[Apollo 刷新](https://www.apollographql.com/docs/react/data/refetching)。本项目具体行为以上述标准及实现为准。
