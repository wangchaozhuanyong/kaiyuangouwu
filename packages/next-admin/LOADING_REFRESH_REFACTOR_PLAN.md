# 管理后台统一重构方案

本窗口只负责 `packages/next-admin`。基线：`192c7fc648a8fe00eef1e5be73ba86786569a0d2`。本地工作区：`.codex-worktrees/admin-unified-runtime-ui-20261003`。用户已授权本地全面重构，未授权推送、合并或部署。

## 目标与边界

所有后台路由、内嵌面板和插件消费同一查询运行时、页面状态、刷新入口及交互组件。沿用 Apollo、React Router、现有主题、业务接口和权限。不增加依赖，不改数据库、支付或登录业务。不修改客户端或根目录规则。

已有紧凑布局、主题边框、标签保留和旧店铺响应拦截继续复用。主工作区及其他窗口的未提交改动不纳入本次工作。

## 公共机制

1. Apollo 是唯一服务端数据缓存。运行时只记录查询身份、所属页面、活动状态、更新时刻及正在进行的刷新；不复制一套全局数据缓存。
2. 查询身份由实际 document、规范化 variables、请求 context 和当前作用域版本组成。切换店铺的既有 response link 继续拒绝旧响应。缓存及页面在店铺切换时沿用既有清理流程。
3. 同一资源并发刷新合并。手动刷新覆盖页面已启用的查询，依赖资源分阶段刷新；筛选条件改变后的查询按新身份重新登记。跳过的弹窗查询不会被强行发起。
4. 首次读取、可用数据、后台更新、已有数据更新失败、无数据错误分开呈现。刷新期间保留同一条件下的数据；不同条件不伪装为最新结果。局部失败保留其余模块，并提供局部重试。
5. 隐藏标签、隐藏浏览器窗口及离线状态停止自动轮询；恢复活动后只更新已过期或失效的数据。时间显示使用公共活动定时器，避免每个页面各自维护后台计时任务。
6. 成功业务写入及真实订单事件使相关资源失效。后台更新失败单独显示，不声称写入失败，也不重放写操作。
7. 编辑页保留本地草稿。新的服务端结果不能直接覆盖脏表单；关闭标签、离开后台或切换店铺前执行已有草稿确认。草稿仅在内存中保留，不持久化敏感内容。

## 统一交互与设计

- 页面保留熟悉的导航、内容、操作与品牌；使用主题语义变量，统一按钮、输入、搜索、刷新反馈、页面骨架、错误边界及表格状态。
- 一个任务只有一个最强主操作；筛选和刷新使用次级操作。列表强调比较、状态与必要操作，不用固定高度制造空白。
- 搜索输入即时响应，查询提交防抖；中文输入法组合期间不提交，回车与清空立即提交。
- 页面异常留在当前标签，导航和其他页面仍可使用。构建资源过期恢复必须先保护草稿。
- 桌面保留数据密度；触摸设备扩大可点击区域。保留表格内横向滚动，不允许整个页面溢出。支持键盘焦点、错误提示、减少动态效果和浅深主题。

## 迁移与验收清单

按公共运行时 → 工作台/商品列表/商品编辑验证 → 销售/客户/营销/店铺内容/设置/插件全量接入 → 清理旧路径的顺序执行。查询接入覆盖统计以源码检查为证据，不能用代表页面测试代替全部业务验收。

- 查询、轮询及手动刷新入口统一；不允许页面直接绕过公共查询适配器。
- 工作台刷新包括指标、待办、最近订单、搜索状态及启用的扩展面板。
- 商品列表刷新包括商品、成本和店铺分配；变更 ID 后的依赖查询不读取旧 ID。
- 标签保留筛选、滚动和草稿；隐藏页不轮询；关页释放登记资源。
- 重复刷新、弱网、失败重试、作用域切换和异步草稿更新具备定向契约测试。
- 实际页面在桌面/手机、浅色/深色下验收；测试数据和真实后台数据明确区分。
- 商品列表曾出现的 502 属于独立服务端/网关问题，需日志证据才能闭环；前端错误提示不是根因修复。

最终交付记录代码、定向测试、类型/构建、浏览器验收及尚未验证部分。不宣称未经验证的线上结果。

## 跨端行为约定

客户端窗口提供的方案与后台一致：首载有占位、刷新保留有效数据、局部错误可重试、作用域切换丢弃旧响应、写操作防重复、写入结果与刷新结果分开。客户端保留 TanStack Query；后台保留 Apollo。两端不共享查询缓存，各自维护包内规则，不修改根 AGENTS.md。
